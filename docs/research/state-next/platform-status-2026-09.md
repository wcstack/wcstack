## Notes

- **#2 Signals**: README still says Stage 1 and states Stage 2 is contingent on framework-integration prototyping; no plenary presentation recorded since 2024-06. `signal-polyfill` has had no release since 0.2.2 (2025-01-17).
- **#3 Observable**: Mozilla's negative position (closed issue, labels `position: negative`, `concerns: venue`) is the blocker; WebKit is `position: support` but has not shipped. Firefox meta bug 1871732 exists but BCD lists no flag.
- **#4 Scoped registries**: the spec property is `ShadowRoot.customElementRegistry` (and `Element.customElementRegistry`, `<template shadowrootcustomelementregistry>`), not `ShadowRoot.customElements`; BCD has no `customElements` entry. Firefox support is Nightly-only (pref enabled by default in Nightly) as of Fx 156.
- **#5 DOM Parts**: nothing has shipped anywhere. Do not confuse with `<template for>` + `<?start>/<?end>` processing-instruction ranges, which **did** ship in Chrome 150 (WF `template-for`, WHATWG HTML `attr-template-for`; Chrome only) for out-of-order streaming — a different feature.
- **#6 Multiple import maps**: Firefox 150 has it only behind `dom.multiple_import_maps.enabled`, so pages must still assume a single map for Firefox. `integrity` is supported by all three engines but web-features has no separate Baseline entry for it.
- **#7 / #8 Temporal & ERM editions**: tc39/proposals `finished-proposals.md` lists publication year **2027** for both; some press (Socket, Igalia) reports Temporal as "ES2026". The table is the primary source. Temporal is in STP 249+ but absent from the Safari 27.0 (2026-09-17) release post; ERM in Safari is "preview" per BCD only (no STP note fetched).
- **#10 AbortSignal.any()**: WF 3.39.0 still lists Newly, but its low date (2024-03-19) crossed the 30-month Widely threshold on 2026-09-19; expect the next web-features release to flip it.
- **#12 Navigation API**: `precommitHandler` (Chrome 146, Firefox 148, Safari —) is a separate, non-Baseline feature (WF `navigation-precommit-handlers`).
- **#13**: Safari 17.4–18.6 `setHTMLUnsafe` was partial (custom elements in declarative shadow roots not upgraded, bug 296420); full from 26. Sanitizer `setHTML()` is Chrome 146 + Firefox 148 only.
- **#15 Reference Target**: shipped by default in Chrome 152 while the WHATWG PRs remain open and WebKit has stated no position; Firefox and Safari have flag-only implementations.
- **#17 DSD**: `shadowrootserializable` has no Firefox support per BCD; `shadowrootdelegatesfocus` is in all three engines (Chrome/FF 123, Safari 16.4).
- **#18 @scope**: BCD dates the at-rule to Chrome 118, but web-features gates the bundle (CSSScopeRule.start/end, nesting inside @scope) at Chrome 143, hence the Baseline date of 2026-03-24 only after Safari 26.4 fixed `<input>`/`<textarea>` handling.
- **#19**: cross-document view transitions are separate and not Baseline (Firefox has none); Firefox 147 supports SPA view-transition types only.
- **#23**: Safari's `Error.isError` (18.4) is flagged partial because it returns `false` for `DOMException`, so web-features treats Safari as unsupported and the feature has no Baseline.

**Not verified**: which STP build enabled Explicit Resource Management in Safari (BCD "preview" only); whether Temporal is enabled by default vs. behind `--useTemporal` in the STP stable channel path beyond the STP 249 note; the Interop 2026 inclusion claim for scoped registries (seen only in a search summary, not fetched). All other cells were checked against fetched sources.
