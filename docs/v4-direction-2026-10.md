## 0. 一言で

4.x で極めるのは、エンジンの速さでも小ささでもなく、**パッケージ同士の継ぎ目の予測可能性** — 作者の意図どおりに動くか、そうでなければ必ず何かが知らせること。

## 2. なぜ継ぎ目か

- 3.x → 4.0 はパッケージの**中**（エンジン）を作り直した。その成果は 1.07 と 20 KiB に出ていて、残りの伸びしろは小さい。
- 4.0 の後の欠陥は、すべてパッケージの**間**（state × storage、state × fetch、router × レイアウト、signals × router）か、時間の経過（再読み込み、2 回目、ディープリンク）の後に出て、ほとんどが無言だった（[seam-apps.ja.md](./seam-apps.ja.md) の「なぜ」）。
- 継ぎ目はプロトコル（wc-bindable・command-token・event-token・binder・transition-runner）が支える場所で、エンジンを書き直しても残る資産でもある。

## 3. 4.x で極めること

### 3.1 沈黙をゼロにする — 誤りの目録

- 継ぎ目アプリの手順 5「よくある間違いをわざとする」を、アプリごとの使い捨てから常設の目録にする。項目ごとに「誤り → 何が知らせるか → 根拠」を持つ。正本は [mistake-catalogue.ja.md](./mistake-catalogue.ja.md)。
- 知らせる層の序列: **設計で消す ＞ 実行時に知らせる ＞ lint ＞ 文書**。lint だけが知らせるものは「条件付きの沈黙」として数える。
- 指標: 目録の項目数と、そのうち無言（文書だけ）の数・lint だけの数。サイズのゲートと同じく、数字で追う。

### 3.2 継ぎ目アプリを制度にする

- 4 本で 79 件の引っかかりが見つかった。今いちばん効く発見の手段だが、越えた継ぎ目はまだ 4 つ。
- まだ越えていない候補:
  - **SSR × router × state** — `@wcstack/server` のハイドレーション、版の門と `legacy()`。互換の論理がいちばん込み入っているのに、継ぎ目アプリが無い
  - **デバイス系の I/O × 権限** — camera / recorder × upload、audio / midi。拒否・取り消し・タブが裏に回る
  - **フレームワークの中の `wcs-*`** — React / Vue から wc-bindable のアダプター越しに
  - **本番の形** — 版の固定・SRI・厳しい CSP・分割エントリ
- 方法は [seam-apps.ja.md](./seam-apps.ja.md) のとおり。発見はそこの記録と目録の両方に入れる。

### 3.3 足さずに直す — 罠の目録を 5.0 の議題にする

- 目録の罠のうち lint か文書でしか知らせていないものを、3 つに分ける: (a) 既定や振る舞いを変えれば消える、(b) 実行時に知らせられる、(c) 静的にしか見えない。
- (a) の多くは正しいページにも影響する（破壊的）。4.x では入れずに目録に記録し、**5.0 の議題はエンジンの書き直しではなく、この (a) から作る**。互換を壊さない (a) は 4.x で入れてよい。
- (b) は 4.x で入れる。`@wcstack/state` の core は残り 536 B なので、原則として diagnostics の後付けに置く。
- 表面積（README の行数・lint の code の数・公開 API の数）は上限を設けず、リリースごとに増えた分を記録する。

### 3.4 最後の既知の穴を閉じる

- **F26（#365・#401）** — 同じオブジェクトが 2 か所にある形。唯一の既知の制限。core の残り 536 B と相談になる。
- **`data-wcs-ignore`（R10）** — CSTI への備え。4.x で足すと決めてあり、足すのは互換を壊さない。
- **メモリ** — js-framework-benchmark のメモリの幾何平均は 4.0 1.95・signals 1.41・3.5.4 4.40。測った軸で 4.0 が最良でないのはここだけ。
- **wc-bindable の applier profile** — 自分のプロトコルの A2（値の後の `undefined` を書く）と A3（完了を呼び手に返す）を、state は名乗っていない。名乗らないまま確定させるか、追いつくかを 4.x の間に決める。

## 4. 進め方

- **リリースの単位**: minor 1 回につき継ぎ目アプリ 1 本。patch はデータ損失と退行だけ。1 回のリリースごとに npm・provenance・SRI・拡張・skill・サイトを確かめるので、週に 8 回の頻度は続かない。
- **4.3 の始め**: 目録の骨組みと、lint だけで拾っている検出の棚卸し（[mistake-catalogue.ja.md](./mistake-catalogue.ja.md)）。続けて、3.4 の F26 と `data-wcs-ignore`。継ぎ目アプリは SSR から。
- **4.x の完成の定義**（目安）:
  - 目録の無言の項目が 0（すべてが設計・実行時・lint のどれかで知らせる、または 5.0 の議題として記録されている）
  - §3.2 の継ぎ目すべてに、意図を確かめる e2e 付きの継ぎ目アプリがある
  - 既知の制限が 0
  - `core.min.js` が 20 KiB 以下のまま

## 5. 決めたこと（2026-10-17、著者）

1. 4.x の主題を「沈黙ゼロ（継ぎ目の予測可能性）」にする。
2. 5.0 の議題を、罠の目録の (a) から作る。
3. リリースの単位を「継ぎ目アプリ 1 本で minor 1 回」に寄せる。

### 5.1 ssr-news から決めたこと（2026-10-18、著者）

最初の継ぎ目アプリ（[seam-apps.ja.md](./seam-apps.ja.md) の ssr-news）が残した設計の問い。6 つとも推奨の案に決めた。

1. **束縛が始めた要求をサーバーが待つ。** 状態から `url` を受ける `<wcs-fetch>` の要求も、描画の時間切れ（`timeoutMs`）の範囲で待つ。待たないと「Loading…」が黙って配られる。
2. **`@wcstack/server` は `@wcstack/state` にちょうどの版で依存する。** 全パッケージを同時にリリースするので失うものは無い。描画するエンジンが server の版で決まる。
3. **`<wcs-state src>` をサーバーで描けるようにする。** `renderToString` に、`src` の URL をローカルのファイルへ解決する選択肢を足す（厳しい CSP の下で文書が勧める形）。
4. **ハイドレーションの前に入力した文字を勝たせる。** 採用のとき、フォーム部品の今の値がマークアップの既定値と違えば、状態から書かずに、その値を状態へ書き戻す。
5. **README の未リリースの機能は「4.3 から（未リリース）」と書き、リリースで「（未リリース）」を外す。** main の README は npm の `latest` より先に進むので、読者が版を見分けられるようにする。
6. **実行できない I/O コマンド**（状態が整っていないために拒んだもの: 未接続の `<wcs-ws>` の `send`、チャンネルの無い `<wcs-broadcast>` の `post`、worker の無い `<wcs-worker>` の `post`、ストリームの無い recorder の `start`）**は、1 要素につき 1 回 `console.warn` する**（`[wcs/command-not-ready]`）。`error` の出力にも従来どおり流す。環境に API が無いもの（unsupported）は `supported` で検出する設計なので含めない。比べた案: `error` だけのまま＋lint、拒むたびに警告、貯めて整ったら送る（遅れて届く方が危ない送信がある）。

### 5.2 7GUIs の評価から決めたこと（2026-10-18、著者）

外部の評価（AI の作者が 7GUIs の 7 課題を 4.2.0 で作り、誤りを 34 件わざと入れた。何も知らせなかったのが 10 件）が残した設計の問い。3 つとも推奨の案に決めた。確実に直せるものは先に入れた: 外部 state（`src=`）へのスクリプトの規則、lint の規則 3 つと拡張 3 つ、`$postUpdate` のパスと宣言に無いキーへの書き込みの警告（PR #484〜#486）。

1. **購読者のいないコマンドの emit は、トークンごとに 1 回 `console.warn` する**（`[wcs/command-token-unbound]`、diagnostics の後付け）。要素の定義が遅れる間（autoloader、遅い CDN — Timer）、同じ更新で描かれる `if:` の枝の受け手（Cells）、受け手の無いトークンが、どれも黙って消えていた。隠れた枝へわざと emit する書き方にも 1 回は出る。比べた案: 一度も購読者を持たなかったトークンだけ（枝の描き直しを取りこぼす）、lint と DevTools のまま。貯めて後で送る案は §5.1 の 6 と同じ理由で採らない。
2. **委譲されたハンドラが throw したとき、そのハンドラのソースが `currentTarget` を含めば、ハンドラごとに 1 回 `#direct` を案内する**（`[wcs/delegated-current-target]`）。core に失敗を後付けへ渡すフックを 1 つ足す（33 B）。throw しない形（`currentTarget.value` が `undefined`）は黙ったままで、ハンドラの間だけ `currentTarget` を要素にする案は 5.0 の議題のまま。
3. **`$postUpdate` の「すべての行」の形は足さない。** `*` は getter と同じく今の行を指すと README に書き、目録で 5.0 の議題にした（`$getAll` の `[]` に当たる形を足すか、行の文脈が解決しない `*` を拒むか）。

### 5.3 state-field-report から決めたこと（2026-10-19、著者）

§3.2 の 2 本目の継ぎ目アプリ（デバイス系の I/O × 権限。[seam-apps.ja.md](./seam-apps.ja.md) の state-field-report）が残した設計の問い。3 つとも推奨の案に決めた。

1. **録画中に `<wcs-recorder>` が文書から外れたら、撮った分をクリップにして渡す。** 何も言わずに捨てていた。権限の取り消しでトラックが終わったときと同じく、止めて `recorded` で渡し、`recording: false` を知らせる。比べた案: 捨てて 1 回警告する。
2. **このページで使えない機能（安全でない origin・Permissions-Policy）は、見張り役も取りに行く側の `permission` も `unsupported` にそろえ、`errorInfo` は理由付きの `capability-missing` にする。** Chromium の Permissions API はポリシーで切られたフレームで `granted`、安全でない origin で `denied` を返し、利用者の拒否と区別できなかった。`denied` は「サイトの設定で変えられる拒否」だけになる。値は増やさない。比べた案: 5 つ目の値（`blocked`）と新しい code を足す、文書だけ。
3. **切断は、変える state の出力をすべてその場で知らせ、打ち切る操作は終わったと知らせる — I/O ノードのファミリー全体の規則にする**（[timing-and-firing-contract.ja.md](./timing-and-firing-contract.ja.md) §22）。router は離れたルートのノードを束縛ごと戻すので、無言のリセット（`speaking`・`listening`）や世代の守りが捨てた完了（`loading`・`connected`）は、戻った後も state の中で古いままだった。洗うと 13 パッケージにあった。§13.4 の「無音のリセット」は「戻して知らせる」に変わる。比べた案: 見つかった camera と recorder だけ直し、残りは目録に記録する。

## 6. やらないこと

- 新しい I/O ノードのパッケージを増やすこと（量産の候補は尽き、パッケージ数は KPI にしない — [go-to-market-2026-08.md](./go-to-market-2026-08.md) §7）。
- 速さの追い込み（CPU は vanillajs と 5 % の差）。
- `data-wcs` への式の追加（配線であって DSL ではない）。
- 4.x の中での破壊的変更（49 のパッケージが同じ版で動くので、major の費用は大きい）。
- 普及のための施策（目的関数は工芸）。ただし、予測可能性を最後に判断するのは自分以外の作者で、人の目に触れる経路が無い状態（検索の該当なし）は、これとは別に判断する価値がある。
