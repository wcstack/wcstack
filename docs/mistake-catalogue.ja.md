# 誤りの目録

**English**: [mistake-catalogue.md](./mistake-catalogue.md)

この目録は、アプリの作者が wcstack で犯しうる誤りを並べ、それぞれについて何が作者に知らせるかを記録します。[v4-direction-2026-10.md](./v4-direction-2026-10.md) の 4.x の目標、**黙って壊れない** — ページは作者の意図どおりに動くか、そうでなければ何かがそう言う — の記録です。

4.0.0 の後に見つかった欠陥は、ほとんどが無言でした。2 つのパッケージの間にあり、時間が経って初めて現れました（[seam-apps.ja.md](./seam-apps.ja.md)）。直すときは、たいてい lint の規則を足しました。この目録は、まだ無言のものを数えて、一つひとつの直し方を比べられるようにします。

## 何が作者に知らせるか

強い順に 4 つの層:

1. **設計。** その誤りは書けない、または害が無い。知らせる必要が無い。
2. **実行時。** 動いているページが throw するか、コンソールにエラーか警告を出す（`wcs/` の code の有無は問わない）。diagnostics の後付けの無い `@wcstack/state/core` のページは番号（`#47`）だけになるが、それも数える。作者はページを試す中で目にする。
3. **lint。** `wcs-validate`・`wcs-tsc`・VS Code 拡張。lint だけが知らせるものは**条件付きの沈黙** — lint を回さない作者には届かない。2026-07 の初見の計測では、AI の作者は 9 回のどれでも回さなかった — サイトでコマンドを読んだ回も含めて。
4. **文書。** README・スキル・設計メモが言うだけで、ほかに何も知らせない。これは**沈黙**。

4.x の目標は、層 4 の項目を 0 にすること。次の目標は、情報がある所で層 3 の項目を層 1 か 2 へ上げること。

実行時の欄は、全部入りの入口（`/auto` と `.`。すべての後付けを入れる）について書く。文書が作者に読み込ませるのはそれだから。`/core` で違うときは、その項目に書く。

## 項目が持つもの

| フィールド | 意味 |
|---|---|
| `id` | kebab-case の名前（一意） |
| `mistake` | 作者が書くもの、1 文で（en・ja） |
| `effect` | 利用者に何が起きるか、または実行時がどう知らせるか（en・ja） |
| `harm` | `data-loss`・`security`・`wrong-place`（出ない・違う場所に出る）・`stale`・`broken`・`degraded` |
| `lint` | 知らせる lint の code と、それぞれの重大度（検出の経路で変わるときは `varies`）。場合ごとに実行時の振る舞いが違う code は、複数の項目に現れてよい |
| `runtime` | `designed-out`・`same`（実行時も同じ `wcs/` の code で知らせる）・`loud`（code の無い throw かログ）・`silent` |
| `evidence` | `same` と `loud` のとき: 実行時の文面を含むファイルとその文字列。`silent` では任意 |
| `disposition` | 実行時が知らせない誤りの扱い。下を参照 |
| `breaking` | `design-out` のとき、その変更が今正しいページに影響するか |
| `note` | 項目を比べるのに要ること（en・ja） |

一部の lint の code は別に並べ、数えない。道具自身の入力（sidecar の manifest、manifest と実際の宣言のずれ）を検査するもの、JSDoc の型、予約だけで出さない code は、アプリの誤りではないため。

## 扱い

lint だけ、または文書だけが知らせる誤りは、次のどれかを持つ:

- **設計で消す**: 既定か振る舞いを変えて、誤りを起こせない、または害の無いものにする。それが今正しいページを変えるなら**破壊的**で、4.x には入れず **5.0 の議題**に置く（5.0 の議題はこの項目から作る）。破壊的でなければ 4.x で入れてよい。
- **実行時に知らせる**: 実行時に、開発中に知らせるだけの情報がある。4.x で知らせるようにする。`@wcstack/state` では、core に費用がかからない場合を除いて、検査は diagnostics の後付けに置く（20 KiB の上限まで 536 B）。
- **lint の規則**: 文書だけが言う誤りのうち、静的な検査に見えるもの。4.x で規則を足す。
- **lint のまま**: 実行時には見えない。lint がこの誤りの届く最も強い層。
- **どこからも見えない**: 静的な検査にも実行時にも分からない。文書だけが守り。

## 項目を足す

継ぎ目アプリ・サイトのチュートリアル・Issue・レビューが誤りを見つけたら、項目を足す。新しい lint の code にも項目が要る。[scripts/mistake-catalogue.json](../scripts/mistake-catalogue.json) を編集して:

```bash
node scripts/sync-mistake-catalogue.mjs           # 下の表を作る
node scripts/sync-mistake-catalogue.mjs --check   # CI が走らせる
```

`--check` が落ちるのは:

- lint のレジストリ（`packages/vscode-wcs/src/core/diagnostics.ts`）の code が目録に無いとき
- 項目の根拠のファイルが、その文字列を含まなくなったとき（頼っている実行時の文面が消えたかもしれない）
- 実行時が知らせない項目に扱いが無いとき
- 下の表が古いとき

## 目録を作る中で見つけたもの（2026-10-17）

最初の棚卸しで、lint の文面と重大度が 3.x のままの所が見つかった。上の表は今の姿を記録している。

**直したもの**（CHANGELOG の `[Unreleased]`「The lint now follows the 4.0 runtime」）:

- **3.x のことを言っていた文面。**
  - `wcs/script-order` は、台帳がライブで取れないと言っていた。今は info。
  - `wcs/scan-declaration-invalid` は、実行時が読み込みで throw すると言っていた。そうするのは diagnostics の後付けだけ。
  - `wcs/declaration-alias-read` は、正式名を読めと案内していた。それも `undefined`。
  - `wcs/tag-member-unknown` と `wcs/recursion-unsupported` は、黙って無視されると言っていた。
  - レジストリのコメントと、vscode-wcs の README の `/core` の文面の形。
- **実行時より狭い検査。**
  - `wcs/mount-path-invalid` は、空白と段の中の `*` も拒む。
  - `wcs/tag-member-unknown` は、`wcs-*` のタグの `hidden`・`textContent` などの DOM のプロパティも見る。
  - manifest の `lt`・`le`・`gt`・`ge` は数値だけを受ける。
- **実行時が失敗するのに警告だったもの。** 次は error になった:
  - `wcs/filter-arg-type`（数値の引数）・`wcs/tag-member-unknown`・`wcs/getter-cycle`・`wcs/index-arity`
  - `wcs/token-misconfigured`・`wcs/token-undeclared`（`command.`）
  - `wcs/recursion-unsupported`
  - データを失う `wcs/input-nested-write`

  `wcs/wildcard-rank` と `wcs/binding-path-missing` は、検出が確実でないので warning のまま。
- **3.x から残った規則。** `wcs/binding-type-expectation` は、`else:` 付きの `if:` に boolean を求めていた。この規則は外した。

**残っているもの:**

- `wcs/array-index-assign` は、実行時が支える `this.items[0] = x; this.$postUpdate("items.0")` を報告する（行のパスへの `$postUpdate` は、行を配列の今の値に合わせる）。見分けるには lint がスクリプトのデータの流れを追う必要があり、文書が勧めるのは `this["items.0"] = x`。優先度は低い。
- `wcs/getter-cycle` は条件分岐を見ない。排他な分岐の裏にあって決して回らない循環も報告する（まれ）。

- `<wcs-fetch>` の `value`・`response` を成功として扱う（4xx でフォームが消える）。
- 入れ子の絶対パスの `for:` の中のハンドラが、外側の添字を期待する。
- `<wcs-storage>` のスロットが `null` になる（保存が消える）。
- ガードがモジュールのトップレベルでセッションを読む。ガードがクエリ文字列に頼る。
- Trusted Types の policy 無しで、HTML を `innerHTML:`・`html:`・`<wcs-fetch target>` に入れる。
- 圧縮の道具が SSR の出力のコメントを取り除く。
- 委譲されるイベントと、ページ自身の `stopPropagation()`、別の root へ移した要素。
- 束縛が中身を決める要素の中、`<noscript>`・`<iframe>` の中の束縛。
- 要素への書き込みで行を並べ替え、束ねていない DOM の状態が元の位置に残る。
- リテラルの `url` と、state から来る `Authorization` ヘッダ（最初の要求はそれなしで出る）。
- `<wcs-route>` の中の light DOM のレイアウトの `slot=`。`enable-shadow-root` のレイアウトの `data-wcs`。
- basename の付いたパスを `navigateUrl` に渡す。言語を `/:lang` のルートの引数にする。
- `$stream` の fetch で、`<wcs-intersect>` の端ごとに `page++` する。
- `customElements.whenDefined()` を関門にする。`pending` でなく `defined` で関門にする。
- 要素の定義の前にマウントするフレームワークのアダプター。
- メンバーを `properties` にだけ宣言する、または入力を属性からしか読まないカスタム要素。
- SSR の state の `Date`・`Map`・`Set`・クラスのインスタンス。
- `<wcs-fetch>` の `value` だけを束ねる（HTTP の誤りで一覧が消える）。
- `id:` の無い SSE の再接続。`CLOSED` で終わったストリーム。
- 最初の引数を読む signals の `For` の行。
- 数値の id に文字列で `$eq` する。
- I/O ノードが接続のときにだけ読む入力を、後で変える。
- `<html lang>` が無い、または最初の描画の後で `locale` を変える。
- ほかに害の小さいもの 29 件。
