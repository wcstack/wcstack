# `@wcstack/signals` が遅いままだった理由 — 検討と 4.18 で変えること

- **状態**: 検討と実装、2026-11-07。著者が同じ日に推奨を採りました（§5）。作業は 4.18 のマイナーに入ります（§6）。
- **English**: [signals-performance-study.md](./signals-performance-study.md)

4.0 の書き直しで `@wcstack/state` は js-framework-benchmark で速くなりましたが、`@wcstack/signals` は手を入れず、元の位置に残りました。この文書は、差の測り方、時間の行き先、5 つの試作、決めたこと、作ったもの、残ったことを記録します。

## 1. 差

公式の js-framework-benchmark（keyed、CPU 計測の加重幾何平均、小さいほど速い）で、2026 年 10 月と 11 月の 2 回:

| | 加重幾何平均 |
|---|---|
| vanillajs | 1.02 |
| `@wcstack/state` 4.x | 1.06 〜 1.07 |
| `@wcstack/signals` 4.x | 1.20 〜 1.22 |

7 月、書き直しの前は signals の方が速かった。細粒度の signals（Solid の型）はこのベンチマークで vanilla の近くに来るのがふつうなので、差は型ではなく実装にありました。

## 2. 測り方

jsfb 自身の計測（クリックから描画まで）は数 ms 違う試作を見分けられませんでした。同じページを 2 回測って「行の作成」が 46.8 ms と 67.0 ms。そこで試作は**ページ内の JS 時間**で比べました:

- リポジトリのベンチマークのページ（`packages/signals/__e2e__/benchmark/index.html`）を、版ごとの `dist/` で Chromium（Playwright）に配り、DevTools プロトコルで CPU を 4 倍に絞る。
- jsfb の操作ごとに、アクションを呼んでから `flushSync()` が終わるまでの時間 — 更新の JS の仕事で、レイアウトと描画を含まない。
- 版を巡ごとに交互に、毎回新しいページで。巡 × 繰り返しの中央値。
- 「どこで」は同じ操作の前後で DevTools のサンプリングプロファイラ、メモリは 2 回強制 GC した後のヒープ（jsfb の "run memory": 1,000 行）。

スクリプトはリポジトリに入れていません。方法はこの節のとおりです。

## 3. 時間の行き先

- **1,000 行の作成**: 約 6 割が DOM のネイティブ（`createElement`・`appendChild`・`addEventListener`）、1 割が GC、3 割が JS。JS は行ごとに、`For` の index と今の item のアクセサのための signal を 2 つ（ほとんどの行はどちらも読まない）、effect ごとに observers の `Set`（effect は読まれない）、所有されるノードごとにクロージャ、リアクティブな文字の子ごとに目印のコメントを作り、`bindProp` は prop ごとに正規表現を 2 回走らせていました。
- **10,000 行の削除**: 5 分の 1 が `removeEventListener`。各行の所有者を片付けるときにリスナー 1 本ずつ呼んでいた — 文書から外したばかりで、どのみちリスナーごと回収される要素に対して。
- **行の選択**: 各行の `class` が `selected.get() === item.id` と比べていたので、1 回のクリックで 2 つを変えるために 1,000 の結び付けが再実行されていました。
- **メモリ**: 1,000 行で 2.99 MB。理由は「作成」と同じ。

2 つの案は測って見送りました。テンプレートの複製で行を作るのは DOM の部分で `createElement` より 1 割速いだけ（4 倍で 12.2 対 13.9 ms）で、新しい API に見合わない。呼び出しごとの `isDev()` の読みは「作成」の約 3 %、後に回します。

## 4. 試作

試作はどれも 4.17.0 のソースの上に作り、4.17.0 の dist と比べました（ページ内の JS 時間、ms、中央値。独立に 2 回。この大きさでは ±10 % 以内は揺れ）:

| | 作成 1k | 置換 1k | 更新 10k | 選択 1k | 入替 1k | 削除 1k | 追加 1k | 全削除 10k |
|---|---|---|---|---|---|---|---|---|
| 4.17.0 | 25.1 | 50.4 | 7.9 | 1.4 | 1.6 | 1.6 | 45.2 | 229.2 |
| A | +15 % | −3 % | −14 % | −7 % | −6 % | −6 % | −31 % | 0 % |
| A + B | −8 % | −19 % | −23 % | −14 % | −12 % | −13 % | −32 % | −22 % |
| A + B + C | −13 % | −28 % | −23 % | −7 % | −13 % | −13 % | −29 % | −26 % |
| A + B + C + D | −7 % / −12 % | −15 % / −18 % | −10 % / −6 % | **−86 %** | −12 % | −13 % / 0 % | −27 % / −7 % | −19 % / −27 % |
| A + B + C + D + E | −10 % | −23 % | −5 % | −79 % | −13 % | 0 % | −6 % | −27 % |

（2 つの数字は 1 回目 / 2 回目。C までの行は 1 回目だけ。A の「作成」+15 % と「追加」−31 % は A の変更で説明できる量を超えていて、4.17.0 の dist 自身が 2 回の間に「追加」で 45.2 から 34.9 ms に動いた。両方の回がそろったものだけを結果として読む。）

- **A** — `For` の index と今の item の signal を `each` のアクセサが初めて読まれたときに作る。effect に自分の observers の `Set` を持たせない。所有されるノードをクロージャでなく自身で登録する。`on…` の判定から正規表現を外す。
- **B** — 所有者の片付けで `removeEventListener` を呼ばない。テストが 2 件落ちた: 文書に**残る**要素（リアクティブな子の下で残す要素）のリスナーも残ってしまう。これが B′（§5）につながった。
- **C** — 値が文字のリアクティブな子は目印のコメントを置かず、Text ノードを位置にする。値が初めてノードになったときに目印を置く。
- **D** — `selector()`（Solid の `createSelector`）と、それを通すページの行の class。試作は key の購読を最後の読み手が去っても残していた: 作成と全削除を 5 回した後のヒープが 1.35 MB から 1.90 MB に増えた。
- **E** — 依存の辺を `Set` でなくスロット付きの配列に（Solid の形）。D より時間もメモリも得がなく、コアの変更は大きい: 採らない。

メモリ、1,000 行: A〜C で 2.99 MB → 2.27 MB。

## 5. 決めたこと

著者が 2026-11-07 に推奨を採りました（「推奨で進めて」）:

1. **A と C を採る**（測ったとおりに）。
2. **B ではなく B′**: 所有者の片付けで、要素がまだ文書にあるときだけリスナーを外す（`el.isConnected`）。残る要素は今までどおり外れ、文書から外れた要素（消えた行・作り直したサブツリー・切り離された `SignalsElement` の中身）はリスナーごと捨てられる。`For` は行を片付ける前にそのノードを外すので、リストの全削除は B の得をそのまま受け取る。
3. **`selector()` を足す**。リークを直し（key は最後の読み手が去ったら忘れる）、ベンチマークのページは選んだ行をそれで読む。
4. **この文書**、そして次のマイナー（4.18）で出す。

採らないもの: E、テンプレートの複製。ここで決めないもの: 新しいページを js-framework-benchmark の上流に出すこと。

## 6. 作ったもの

- `packages/signals/src/reactive.ts`
  - 所有者の子は、破棄の関数か `_disposeOwned()` を持つノード。computed と effect は自分を登録する（それぞれのクロージャがない）。effect は空の observers の `Set` を 1 つ共有する。
  - `selector(source)`: key から小さな observable への `Map` を 1 つ。`source` を読む内部の effect が、離れた key と移った key の読み手に印を付ける。`untrack()` は最後の observer が去った observable の `_unobserved` を呼び、その key の項目を消す。計算の外からの呼び出しは `source` を読むだけで何も購読しない。
  - key は `Map` のキーと同じに比べる（SameValueZero）。試作の `equals` 引数は外した: 独自の等価は、`Map` が別のオブジェクトの下に持つ購読を見つけられず、`selected.set({ id: 2 })` が `{ id: 2 }` の読み手に届かない。オブジェクトを選ぶときは `computed` で id を選ぶ。
- `packages/signals/src/dom.ts`
  - `bindProp`: `on…` の判定を文字コードで。リスナーの片付けに B′。
  - `insertReactive`: C — 値が文字のうちは最初の Text ノードが位置。値が初めてノードになったときに、その後ろに目印のコメントを置く。
  - `For`: 行は位置と item をふつうの値で持ち、index / current の signal は初めて読まれたときにそこから作る。
  - `@wcstack/signals` と同じく `selector` を再エクスポート。
- `packages/signals/src/dev.ts`: 重複除けのキーにあった生の NUL 文字を `\u0000` と書く。
- テスト: リスナーのテストを B′ に書き直し（文書にあれば外す、外にあれば残す、3,000 行を消す `For` は `removeEventListener` を 0 回）、目印のない文字の子をすべての遷移で、移動の後に初めて読む index / current、`selector`（読み手の再実行、同じ tick の行って戻り、flush 前の今の値、`NaN`、computed の source と読み手、key を忘れる、計算の外からの呼び出し、片付け、100 行の `For` で選び直し 1 回の再実行が 2 つ）。カバレッジは 100 % のまま。

作者が気づきうること:

- 文書の**外**で片付けた要素のハンドラは外れない: そういう要素を持ち続けてスクリプトからイベントを送れば、ハンドラは呼ばれる。利用者は押せない。
- リアクティブな文字の子の隣にコメントのノードがない: `childNodes` を数えるテストは 1 つ少なく見る。

## 7. 結果

4.17.0 とこの作業を §4 と同じ方法で（4.17.0 はこの変更の前のページ、この作業は `selector` を使うページ）:

| | 作成 1k | 置換 1k | 更新 10k | 選択 1k | 入替 1k | 削除 1k | 追加 1k | 全削除 10k |
|---|---|---|---|---|---|---|---|---|
| 4.17.0、ms（1 回目 / 2 回目） | 25.6 / 27.5 | 56.3 / 48.6 | 7.7 / 7.1 | 1.4 / 1.5 | 1.5 / 1.5 | 1.8 / 1.6 | 50.3 / 40.3 | 235.4 / 232.7 |
| この作業 | +12 % / −9 % | −19 % / −11 % | −8 % / +1 % | **−79 % / −80 %** | +7 % / −7 % | −17 % / 0 % | −30 % / −13 % | −21 % / −23 % |

両方の回がそろったもの: 行の選択が約 −80 %、10,000 行の全削除が −21 〜 −23 %、1,000 行の置換が −11 〜 −19 %、10,000 行への 1,000 行の追加が −13 〜 −30 %。更新・入替・削除は揺れの範囲。「作成」は回の間で最も動いた — 4.17.0 の dist 自身が 25.6 と 27.5 ms — ので、「置換」と 2 つだけでもう一度測った（6 巡 × 10、試作を並べて）: 作成 −16 %（A + B + C −13 %、D の試作 −10 %、`selector` を使わないページでのこの作業 −13 %）、置換 −19 %（−24 %、−22 %、−19 %）。

2 回強制 GC した後のメモリ:

| | 4.17.0 | この作業 |
|---|---|---|
| 1,000 行 | 2.99 MB | 2.63 MB |
| 作成と全削除を 5 回した後 | 1.36 MB | 1.36 MB |

2 行目がリークを直した分: D の試作はここで 1.90 MB を持っていた。A〜C が 1,000 行で減らした 0.72 MB のうち約半分を、`selector` の key ごとの購読（それぞれ `Set` を 1 つ）が取り戻す。その購読をクロージャ付きのオブジェクトでなくクラスにしても測れるほどは減らなかったので、オブジェクトのままにした。

## 8. 残ったこと

- **イベントの委譲** — イベントの種類ごとに根に 1 本のリスナー、ハンドラは target から探す — は最速のライブラリが「作成」と「全削除」でしていること。`h()` のハンドラの付け方（と `currentTarget` が何か）を変えるので、それだけの設計が要る。
- **`isDev()`** は警告しうる呼び出しのたびに読まれる。操作ごとに 1 回にすれば「作成」の約 3 %。
- 新しいページは公式の計測でまだ走らせていない。§7 から加重幾何平均は 1.13 〜 1.15 あたりと見積もるが、見積もりで計測ではない。
