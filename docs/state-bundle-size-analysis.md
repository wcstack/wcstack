# State bundle size analysis

**日本語版**: [state-bundle-size-analysis.ja.md](./state-bundle-size-analysis.ja.md)

- Analysis date: 2026-09-16.
- Target: `@wcstack/state` v2.4.0 (`e67e178d`); the analyzed checkout was `596d0c15`, with the same state package source.
- Status: measured findings and proposed follow-up work. No runtime or packaging change is implemented by this document.

## Summary

Three separate issues account for the size:

1. The standard ESM entry ships without minification, including substantial comments. Direct browser imports pay for the whole file.
2. The default runtime includes optional application features such as `$scan`, `$recursion`, streams, DCC, and SSR through static imports.
3. Module-level listener registration retains much of the runtime even when a bundler consumes only `defineState`.

There are no production package dependencies responsible for this growth. Start with distribution and initialization boundaries, then evaluate feature separation. Removing DevTools alone would yield a comparatively small reduction.

## Measurement conditions

- Windows, Node.js 22.19.0, Rollup 4.56.0, Terser 5.46.0, TypeScript 5.9.3; installed state package tooling.
- Ran `npm run build` in `packages/state`. The build succeeded, with existing circular-dependency and TypeScript `inlineSources`/source-map warnings.
- Current JavaScript measurements use fresh build output with LF line endings. Historical measurements read Git blobs with `git show <tag>:packages/state/dist/<file>`, avoiding checkout CRLF conversion.
- All sizes are UTF-8 bytes. KB means 1,000 bytes. gzip uses level 9; Brotli uses quality 11 through Node's `zlib`.
- Compression numbers are local measurements, not observations of CDN response headers, transfer sizes, startup time, or memory usage.
- Minification experiments used Terser with `module: true`. Single-export experiments used Rollup's default tree-shaking followed by that minification.
- Source-map attribution assigns generated byte spans between adjacent mapping segments to the mapped source file. It is approximate, especially across optimized expressions; it does not establish the saving from removing a feature. gzip contributions cannot be added independently.

## 1. Distribution size

| Artifact / experiment | Bytes | gzip bytes | Brotli bytes |
|---|---:|---:|---:|
| `dist/index.esm.js` | 1,079,910 | 298,401 | 217,523 |
| `dist/auto.min.js` | 229,206 | 66,981 | 56,879 |
| Minify `index.esm.js` in memory | 238,101 | 69,285 | 58,732 |
| Remove comments from `index.esm.js`, retain readable formatting | 580,438 | 108,436 | 85,423 |

The comments experiment used `compress: false`, `mangle: false`, and `format: { beautify: true, comments: false }`; formatting changes mean its delta is not an exact count of comment bytes.

Minifying the named-export bundle reduces its measured gzip size by **76.8%**, without intentionally removing any public feature. This is a size experiment, not semantic regression testing of a new distribution artifact.

The [shared Rollup template](../config-templates/rollup.config.js) deliberately omits `index.esm.min.js` when a self-contained `auto` bundle exists. The [state package exports](../packages/state/package.json) therefore offer an unminified named-export entry and a minified auto-bootstrap entry. These have different initialization behavior; `auto` is not a drop-in replacement for a named import. A buildless browser import does not tree-shake the downloaded file. An application bundler may minify it, subject to the retention issue in section 4.

The tracked v2.4.0 `dist` files total **4,898,276 bytes**, of which the two source maps account for **3,379,540 bytes (69.0%)**. These figures use tracked Git blobs, not the locally regenerated maps, whose embedded source contents differ with checkout line endings. They describe the unpacked `dist` directory, not an npm tarball. Source maps are not part of ordinary runtime JavaScript loading, although debugging tools may request them.

| v1.30.0 | 152,046 | 43,367 |
| v1.33.0 | 169,749 | 48,831 |
| v2.0.0 | 182,642 | 52,977 |

| v2.1.1 | 183,257 | 53,148 |
| v2.2.0 | 190,099 | 55,292 |
| v2.3.0 | 208,741 | 61,139 |
| v2.4.0 | 229,206 | 66,981 |

From v2.0.0 to v2.4.0, minified JavaScript grows **25.5%** and gzip grows **26.4%**. Source-map comparisons locate the recent increases:

- **v2.2.0 → v2.3.0:** +18,642 bytes total; `recursion/` contributes approximately +14,320 bytes (76.8% of the increase), with another +1,867 bytes in `proxy/`.
- **v2.3.0 → v2.4.0:** +20,465 bytes total; `scan/` contributes approximately +14,851 bytes (72.6%), followed by `components/` (+1,662), `watch/` (+1,404), and `list/` (+1,331).

These are changes in attributed bytes between builds, not controlled estimates of the entire cost of each feature. Older releases such as v1.25.0 used a 78-byte `auto` stub importing `index.esm.min.js`; comparing that stub alone against today's self-contained bundle would be misleading.

The largest individual files are `components/State.ts` (16,952 bytes) and `bindings/BindingSession.ts` (12,910 bytes). The selected rows above do not cover every file.

[State.ts](../packages/state/src/components/State.ts) imports streams, watch, scan, recursion, DCC, and SSR directly. [bootstrapState.ts](../packages/state/src/bootstrapState.ts) registers components, the binder, the SSR snapshot builder, and the DevTools source. Not declaring an optional feature in an application's state can avoid executing its work, but does not remove its implementation from `auto`.

SSR-related files (`components/Ssr.ts`, `hydrateBindings.ts`, `buildSsrDocument.ts`, `apply/ssrPropertyStore.ts`, and `protocol/ssrSnapshot.ts`) account for about **10,086 bytes**, spread across the directory totals and root files. This is not additive to those totals and excludes SSR branches inside other files.

The main entry re-exports the contract analyzer, filter metadata, and manifest API through [exports.ts](../packages/state/src/exports.ts). They are absent from the generated `auto` map: tree-shaking already removes them there. DevTools-specific files total only about 3.7 KB; instrumentation in other modules is not included in that directory figure.

## 4. Single-export retention

An entry that re-exports only `defineState` from `dist/index.esm.js` still retains substantial code:

| Experiment | Minified bytes | gzip bytes |
|---|---:|---:|
| `defineState` from the standard entry | 87,349 | 26,149 |
| Same entry with two module-level registrations removed in memory | 6,238 | 1,943 |
| Bundle `src/defineState.ts` directly after TypeScript transpilation | 48 | 68 |

The two registrations are:

- `registerUpdateBatchListener(fireWatchOnUpdateBatch, WATCH_LISTENER_PRIORITY)` in [watchRuntime.ts](../packages/state/src/watch/watchRuntime.ts).
- `registerUpdateBatchListener(restartStreamsOnUpdateBatch, STREAM_LISTENER_PRIORITY)` in [streamRuntime.ts](../packages/state/src/stream/streamRuntime.ts).

They execute during module evaluation. Rollup retains the listeners and their transitive references, including update and DOM-binding code. This also affects a `VERSION`-only export (87,332 minified bytes; 26,161 gzip bytes).

Removing the two calls was an in-memory diagnostic, **not a valid runtime fix**: it omits required behavior. A real change needs explicit, idempotent registration at the appropriate initialization boundary, preserving listener priority and startup behavior. The remaining 6.2 KB also shows that these calls are not the only retention source. A blanket `sideEffects: false` declaration would not establish that removal is safe.

A dedicated subpath for `defineState` would avoid importing the runtime graph. The 48-byte direct-source experiment measures the helper implementation, not a currently published entry.

## 5. Recommended follow-up order

1. **Provide a minified named-export distribution.** Choose an explicit subpath or distribution policy; preserve the distinction between bootstrap and named APIs. Edit the Rollup template/source and run the synchronization script rather than changing generated copies. Preserve the self-contained `auto` artifact required by [SRI](./sri.md).
2. **Separate helper imports and runtime initialization.** Add a lightweight `defineState` entry and move required listener setup to an explicit, idempotent boundary. Test initialization, listener ordering, and repeated bootstrap as well as bundle size.
3. **Design optional feature boundaries.** Evaluate scan, recursion, SSR, streams, and DCC. Moving files alone will not help while State and the updater statically reference them. Preserve existing default behavior or treat a changed default as an API migration. Directory attribution is not a promised reduction.
4. **Add CI size budgets.** Track `auto` raw/gzip size, the named-export distribution, and a `defineState`-only consumer. Keep transfer budgets distinct from unpacked package and source-map budgets. The signals package already has a [size-limit configuration](../packages/signals/.size-limit.json); state has no corresponding size script in its package manifest at the analyzed revision.

## 6. Reproduction outline

Use the recorded revision and dependency versions. In a disposable checkout, run `npm run build` from `packages/state`; the command regenerates tracked `dist` artifacts, including maps. For each file, measure `Buffer.byteLength`/buffer length and Node's `gzipSync(buffer, { level: 9 })` and `brotliCompressSync(buffer, { params: { [constants.BROTLI_PARAM_QUALITY]: 11 } })`.

For historical sizes, read each artifact using `execFileSync('git', ['show', '<tag>:packages/state/dist/auto.min.js'])` and compress the returned buffer. For source attribution, decode the matching `.map` with `@jridgewell/sourcemap-codec`, assign each generated segment through the next segment's column to its source, and aggregate UTF-8 lengths by directory. Do not count unmapped spans as a feature.

For single-export experiments, use a virtual Rollup entry containing `export { defineState } from '<absolute path>/dist/index.esm.js'`, generate ESM with default tree-shaking, then call `terser.minify(code, { module: true })`. For the diagnostic variant, remove only the two complete registration statements identified in section 4 from an in-memory copy of the input bundle before running the same pipeline. For the direct helper, transpile `src/defineState.ts` with ESNext modules, ES2022 target, and comments removed, then apply the same export and minification pipeline. Generated identifier spelling can depend on the input entry, so retain the measured bytes as a baseline rather than an invariant across tooling changes.

Validation performed for this analysis: successful package build, compression measurements, historical artifact comparisons, source-map attribution, and in-memory bundling experiments. Runtime tests and browser performance benchmarks were not run; no behavior change was proposed as already verified.
