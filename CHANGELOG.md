# Changelog

All notable changes to the wcstack packages are documented here. All published `@wcstack/*` packages and the `wcstack` entry package share one version and are released in lockstep; a release bumps every package whether or not it changed. The VS Code extension (`packages/vscode-wcs`) is versioned separately and keeps [its own changelog](./packages/vscode-wcs/CHANGELOG.md).

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). What counts as a breaking change is defined in the root README under [Versioning and breaking changes](./README.md#versioning-and-breaking-changes). Upgrading from 2.x: read the [v2 → v3 migration guide](./docs/migration-v3.md) first; from 1.x, the [v1 → v2 migration guide](./docs/migration-v2.md).

Each GitHub Release also carries the Subresource Integrity digest of every package's `dist/auto.min.js` (and `sri.json`); see [docs/sri.md](./docs/sri.md).

## [Unreleased]

### Fixed

- `@wcstack/state`: **a `for` row no longer renders nothing when it holds an element whose wc-bindable member takes its initial value from the element.** An output-only member (listed in `properties` but not in `inputs` — `<wcs-fetch>`'s `value` / `loading`, `<wcs-intersect>`'s `intersecting`, …) and a two-way member marked `#init=element`, or `#init=auto` on a row whose state has no value yet, pull the element's value into state when the binding is set up. When every row of a render is new — the first render, filling an empty list, a wholesale replacement — the rows are activated on a batch `DocumentFragment` before they are inserted, so `getRootNode()` returned the fragment, the state lookup came back empty and the initial sync threw `No state tree found on this root for initial binding sync.` That failed the whole `for:` apply: the list stayed empty with only a `console.error` to show for it, and replacing an already-rendered list with new row objects — a refetch — emptied it as well. It took the element's class being defined before the rows were built, which is always the case with `wcstack/auto` or an I/O node's `auto` loaded first; an undefined class deferred the sync until the rows were in the document. The lookup now resolves a batch fragment to its real root through the same ledger `applyChange` uses, so each row's value is initialized from its own element — also inside a row's `if:`. Present since the directional initial sync shipped in 1.21.0. (#319)
- `@wcstack/state`: **a mounted component's method that writes one of its private keys now re-renders in that pass.** A private key is a data key the component declares itself — the README's `state = { mode: "view" }` — and a method's `this` is the mount overlay. A write from a method or a setter body (`toggle() { this.mode = … }`) was assigned straight into the private data: no enqueue, no dependency walk, no cache update. The value changed, but `{{ mode }}` and any getter over it kept the old value until some unrelated change caused a render. In a row mount (`state: .` inside a host `for:`) the cached read went stale as well, so `element.state.mode` disagreed with the private data and an outside write of the same value was dropped by the same-value guard. Writing through `element.state` from outside was not affected. The author's code now gets a proxy that sends private-key writes through the parent's `setByAddress` — the path a plain state's `this.x = v` takes — including after an `await`, and a row instance's write lands on its own row even if the host reordered the rows in the meantime. A `$postUpdate` added as a workaround keeps working and is now redundant. A regression since 2.0.0: 1.x ran a mounted component on a state tree of its own. Two things that followed from it are fixed with it. In a row mount a method was cached, bound to the session of its first call, so from the second call on a read of a mounted key (`this.name`) threw `ListIndex not found`, and once the method had been fetched through `element.state` every later click wrote without re-rendering; function values are no longer cached. And a batch that updated nothing but private keys still called the root `$updatedCallback` with `([], {})` and fired the DCC `$bindables` change event of the member the component was mounted from — it now does neither. (#321)
- `@wcstack/state`: **a component mounted inside a host `for:` row by a partial mount (`state.items: .items`) can read the mounted keys from a getter.** A partial-only mount has no root entry, so its marker base `#m<id>` carries no row wildcard, and a getter without one (`get total()`) was evaluated with no host row in context. A plain read (`this.items`) threw `ListIndex not found` — README's "Loop with Components" (`state.message: .name`) broke as soon as a getter read `message`; `$getAll` / `$setAll` / `$resolve` threw `Cannot resolve "items.*.v" from this mount: … the host context provides only 0 index(es)`, from methods as well; and `$getAll("items.*.v")` with the indexes omitted did not throw at all — it expanded over every host row and returned values mixed from the other rows (10 / 10 where 3 / 7 was right). The host row now comes from the host element's loop context, the source `element.state` already used, so each instance resolves its own row and follows host writes, row moves and a row's content being reused for another row; the omitted form means the instance's own row, as the mount design (§4-6) specifies. Present since 2.0.0. (#322)
- `@wcstack/state`: **a component inside a host `for:` row can read and write a path with a numeric index in its own vocabulary** — `this["items.0.v"]`, `` this[`items.${i}.v`] `` from a handler, `element.state["items.0.v"]`, and in a whole-row mount `this["drafts.1.t"]` over a private array. The translated path kept the row wildcard in front of the index (`groups.*.items.0.v`), a mix the core does not resolve, so every read and write threw `Partial wildcard type is not supported yet` — with a whole-row mount (`state: .`) too, where `$resolve` and `$setAll` already worked. The prefix is now filled with the host row's indexes (`groups.1.items.0.v`) before the path reaches the core, also for the path-only `$` APIs (`$postUpdate("items.0.v")`, `$eq("items.0.v", 1)`). When a row-mount instance's host row has left the list by the time the path is resolved — a method that resumes after an `await` — the path now throws `The host row of <x-list> was removed.` instead of resolving against whichever row now holds the old position; a `$resolve(path, indexes, value)` from such a method used to write that other row's data. Present since 2.0.0. (#323)
- `@wcstack/state`: **a `for:` that renders the same list as another `for:` now catches up when it comes back after `if:` hid it (or after author code took it out of the DOM) while the list changed.** The diff baseline is one record per list address, shared by every `for:` over that list, while the rendered rows are kept per `for:`; the record moved on with the visible `for:` alone, so the returning one diffed the current array against itself and was told every row was kept. With the Issue's steps — `<ul>` inside `if: showA`, `<ol>` outside, add a row, hide, add another, show — the `<ul>` came back without the row added while it was hidden and then ignored a reverse; replacing every row, replacing one row (`const a = [...items]; a[0] = {…}`), an element write (`this["items.0"] = {…}`) or replacing a parent row of a nested list while hidden left it empty or missing rows. Every release from 1.10.0 through 3.3.0 does this. The throw (`Content not found for ListIndex`) also stopped the rest of the `if:` block, so bindings after the list inside the same `if:` kept their old values, and the only trace was a `console.error` saying `binding "if: showA" failed to apply`. Each `for:` now remembers the rows it rendered and, when the shared record has moved past them, matches its own rows against the current ones by row identity; an element write hands the pre-write copy of the list to every `for:` that rendered it, so a hidden one diffs from what it actually drew. A `for:` whose current rows hang under a different live parent row — a ledger an element write in a nested list can leave behind, an older defect this does not fix — keeps the previous diff, so that defect still fails with `Content not found` rather than drawing another row's values and landing the next write in that row's data. Two views of one list — tabs toggled by mutually exclusive `if:`s, a table and a card view — no longer need the workaround of keeping both mounted and toggling `hidden`. Along the way, the inner `for:` of a row recycled from the pool returns the previous row's child rows to its pool instead of keeping them and creating new ones: its Content ledger used to grow by the previous row's child count on every reuse (6 → 15 over three `map(n => ({...n}))` replacements of a two-row nested list), and the child cells of a replaced parent row are now drawn from that pool. (#320)
- `@wcstack/state`: **a numeric-index path (`this["items.0.v"]`) now reads and writes a list row whether or not a `for:` renders the list.** The README's "Direct index access" has promised since v1.2.0 that `this["users.0.name"]` resolves as `users[0].name` without loop context, and vscode-wcs's `wcs/array-index-assign` / `wcs/nested-assign` errors tell authors to write exactly that (`this["items.0"] = x`) — but it held only for a list something had already diffed: a `for:` render, a `$getAll` / `$setAll`, or a dependency walk. The path looks each list level up in the row ledger, which only a list diff fills, so on any other list the read and the write both threw `ListIndex not found: <list path>` (`items`; `groups.*.items` when only `groups` is rendered; `groups` when neither is) and nothing was written. The issue's page — `bump() { this["items.0.v"] = 7; this.count++; }` — stopped at its first line with `"bump" rejected`, leaving `items[0].v` at 1 and `count` at 0, and a top-level getter reading `this["items.0.v"]` rendered empty, with `binding "prop: first" failed to apply`, unless a `for:` earlier in the page had already rendered the list. A list with no ledger now gets one on the spot, diffed against the same state-side baseline `$getAll` diffs against and recorded as that baseline the way `$getAll` records it, so rows are reused by `$getAll`'s rule, a `for:` that renders the list later adopts the same rows, and replacing the list afterwards retires them — without that last part, a row aggregate rendered after the list was copied (`groups = groups.map(g => ({...g}))`) stopped following leaf writes for good, even when the list had only been read. The same lookup serves a cold `$resolve(path, indexes)` — the one wildcard API that threw (`ListIndexes not found: <list path>`) on a list nothing had traversed — and `$postUpdate("items.0.v")`; warming the list first with a `$getAll` or a hidden `for:` is no longer needed. An index with no row throws `ListIndex not found at index <i> of <list path>` whether or not the list is rendered, including when the value there is `null`, a string or an empty array (it has no rows), and `$resolve` now says the same instead of `ListIndexes not found`. (#324)

## [3.3.0] — 2026-09-24

**3.3 is a quality pass over everything 3.0, 3.1 and 3.2 introduced.** Five reviews, each starting from a clean slate so none inherited the previous one's assumptions, raised 137 findings; 116 are fixed here. The changes are in `@wcstack/state`, `@wcstack/server` and the tooling; every other package moves to 3.3.0 only to keep the lockstep version.

Most of it is forms that used to fail *silently* — a `for` row that rendered nothing, an `else:` that never appeared, a template that lost its `{{ }}` after hydration, a server that stopped answering. A few forms that 3.1 and 3.2 accepted are now refused by name, which is why this is a minor rather than a patch: `.state:` and `.state.<key>:` (the undotted `state:` / `state.<key>:` volume forms are unchanged), an empty path segment on the right of a binding (`a.`, `a..b` — a *leading* dot is still the loop shorthand), text after a filter's closing `)`, a left side that names no property, a `$stream` entry colliding with a state method, and a path over 512 segments. Each of those was already broken at run time; they now say so where you write them. Lint gains `wcs/declaration-alias` and `wcs/declaration-alias-read`, and loses a batch of false positives that made it report on correct code.

### Fixed

- `@wcstack/state`: **a `$stream` entry name that collides with a method on the state now raises, instead of silently destroying that method.** `$scan` has refused the same collision since it shipped (D7), but the `$stream` declaration checked only getters, setters and `Object.prototype` names. With `{ ticker() {…}, $stream: { ticker: {…} } }` the `name in state` test was true, so the value property was never materialized — and then the start-time reset to `initial` overwrote the method through the proxy. Measured: `typeof state.ticker` went from `"function"` to `"number"`, with **zero** console output; every later `this.ticker()` — from a getter, a `$watch` or a command — failed with `not a function` far from the declaration. A class-based state broke the same way (the instance grew an own property shadowing the prototype method). The check reads property descriptors along the prototype chain, so a getter is never evaluated, and it runs in the `_state` setter, well before the streams start: the failure lands on the ordinary initialization path (a `console.error` plus a rejected `connectedCallbackPromise`), not on the eager start. A function value the runtime itself placed there is not a collision — an `initial` that is a function, or a `fold` that returns functions, keeps working across a re-set, sharing `$scan`'s `recordOutputValue` / `wasPlacedOnOutput` ledger.
- `@wcstack/state`: **a `$scan` whose `from` rows could not be placed reported the wrong half of the fold.** `selectLandedRows` reads the list to find where each landed row sits now, so it can throw — and the failure label was still `read-output`, so the console said `$scan could not read the output "x"` when the output had already been read successfully and it was the source list that failed. The new `read-rows` label names the `from` side (`could not read the rows of "from" for "x"`); the DevTools phase stays `evaluate`.
- `@wcstack/state`: the `$stream` "source must return an AsyncIterable or a ReadableStream" `TypeError` says `$stream`, not the pre-3.2 `$streams` — the last old-name literal left in a user-facing message (every other one in `stream/` was already built from `STATE_STREAM_NAME`).

- `@wcstack/state`: **a `for` row whose binding carries a quoted `:` in a filter argument no longer renders zero rows, silently.** `structural/expandShorthandPaths.ts` — the expander that turns a row's `.name` shorthand into `items.*.name` — scanned the three delimiters raw (`split(';')`, `indexOf(':')`, `indexOf('|')`) instead of using the canonical quote-aware helpers. With `value|defaults('00:00'): .startTime` the `:` inside `'00:00'` was taken as the separator, the shorthand was never expanded, `.startTime` reached the binder as a literal path, and the whole template rendered nothing: `getBindingsReady` does not reject, so the only trace was `[wcs/binding-path-missing]` on the console. `defaults('00:00')` / `join(': ')` / `defaults('N/A: なし')` are everyday markup. It also rewrote literals inside quotes (`defaults(';x: .b')` had its `.b` expanded). Worse, the VS Code extension and `@wcstack/lint` do their own shorthand expansion **correctly**, so the page was blank while the tooling was green — this was the last raw delimiter scan on a `data-wcs` value in the runtime. The two remaining raw `split`s (`parsePropPart` / `parseBindTextsForElement`, both operating on the slice before the first unquoted `|`, where a quote cannot appear) now carry the invariant and the condition that would break it.
- `@wcstack/state`: **a filter no longer disappears when the `|` before it is missing.** `parseFilters` took the last `)` in the text and threw away everything after it without looking, so `n|fix(2)uc` silently dropped `uc` while the parenthesis-free `n|ucuc` failed as `[wcs/filter-unknown]` — the diagnosis depended on whether the previous filter had arguments. Trailing text after the closing `)` is now `[wcs/binding-syntax]` and names what to write instead; `foo)1(` (accepted before as a filter named `foo)1`, because `substring` swaps a reversed range) is rejected explicitly; and both parentheses are found outside quotes, so `join(')')` reads its argument instead of mis-reporting an unterminated quote.
- `@wcstack/state`: **an empty path segment on the right of a binding is rejected at parse time**, as it already was on the left. `textContent: a.` and `textContent: a..b` produced no diagnostic at all and interned `["a","",""]`; `textContent:` and `textContent: |uc` failed only when applied, as `[wcs/binding-path-missing] Path ""` — a diagnostic naming the empty string. A **leading** empty segment stays legal: `.name` is the loop-relative shorthand that the row expander and `expandSpread` generate. This is also what would have made the shorthand defect above fail loudly instead of silently.
- `@wcstack/state`: **a single deep path can no longer exhaust the heap.** `PathInfo` interns every prefix of a path, so one path of depth N builds N objects each holding arrays and sets of length k — quadratic in both time and memory. Measured on Node 22 with one path: depth 400 → 145 ms / 61 MB, 800 → 1162 ms / 424 MB, 2000 → out of memory on the default 4 GB heap. A `data-wcs` value of about 4 KB was enough to kill the tab. `getPathInfo` now rejects a path with more than `MAX_PATH_SEGMENTS` (512) segments as `[wcs/binding-syntax]`, before anything is built or interned. The limit is twice `MAX_WILDCARD_DEPTH` so that the documented `$recursion` depth (128 wildcard levels needs 257 segments) still fits; real paths are under ten. The wildcard count itself is deliberately **not** capped here — `recursion/expand.ts` and the `$N` lookup already do that where they can tell a depth overrun from a cycle.
- `@wcstack/state`: **`class.` / `attr.` / `style.` on a wc-bindable element no longer takes the whole root down.** `resolveInitialSyncPolicy` excluded only the `command.` namespace from the wcBindable member check, so a left-hand side in any other namespace fell through to `Property "class.on" is not declared by wcBindable.` — a throw, which means *not one* binding on that root gets wired and `getBindingsReady` rejects. Adding `class.loading: isLoading` to a `<wcs-fetch>` was enough. Of the three faces only the runtime was wrong (the VS Code extension's `ioNodeValidator` and `apply/applyChange.ts` both treat the four namespaces alike), and the file has been this way since 2.6.1, so this is not a 3.x regression — but it only ever throws, so nothing that worked changes. The namespaces now come from one set whose agreement with the apply layer's dispatch table is pinned by a test.
- `@wcstack/state`: **two wc-bindable tags whose `wcBindable` getters differ no longer share one two-way handler.** The handler closure captures the getter *implementation*, but the shared-handler key recorded only whether a getter existed — so two tags on the same state path with the same event name and filters had the second one writing values folded by the *first* tag's getter. The key now carries the getter's identity. Everything the detach needs — the key **and** the event name — is recorded at attach and nothing is read back from the declaration: `wcBindable` declarations are live by contract (a composite shell synthesizes one from `constructor.wcBindable`), so recomputing at detach could take a different branch at the two-way gate, or call `removeEventListener` with a different event name or handler, and each of those leaves the listener attached. The presence of that record is now what "did we attach?" means.
- `@wcstack/state`: **a DOM event handler that throws synchronously is reported instead of sinking into an unhandled rejection.** `event/handler.ts` drives handlers through `createStateAsync`, so a synchronous throw (an undeclared command token, a missing handler name, an exception from the author's method) becomes a rejection of a promise the runtime discarded. That contradicted both the README ("throws at event time") and `captureHandlerRejection.ts` ("a synchronous throw does not pass through here"). A DOM event cannot be thrown back at, so the rejection is now routed to the same `console.error` report; the README says so too. Handlers reached synchronously (two-way / radio / checkbox) still propagate.
- `@wcstack/state`: **`Token.emit` delivers to the remaining subscribers when one throws** (and reports the thrower with `console.error`). A token is a fan-out point whose subscribers do not know about each other — the README's example of wiring `command.clear:` and `command.reset:` to one `$command.reset` did not hold if one element's method threw. Combined with the unhandled-rejection hole above, a DOM-triggered command could silently reach only some of its elements. **Behaviour change:** `emit` no longer propagates a subscriber's exception to the emitter.
- `@wcstack/state`: **the devtools declaration key keeps input and output filters apart.** They were concatenated, so `value|trim: memo` (input) and `value: memo|trim` (output) produced the same key and one of the two was silently dropped from the declared set.
- `@wcstack/state`: **a property binding no longer attaches a DOM event listener.** Whether a binding listens was decided by the spelling of the name (`propName.startsWith("on")`), not by its kind, so the explicit property form `.online:` (3.1, requirement B5) subscribed to a `"line"` event — and, because that path returns early, the row skipped the radio / checkbox / two-way / directional-initial-sync wiring behind it. The same shape reached any `on`-prefixed input wired through `spread` (`once` on `<wcs-timer>` / `<wcs-raf>` / `<wcs-resize>` / `<wcs-intersect>`). The gate is now the binding kind, so a binding means the same thing inside a `for` row (`structural/rowPlan.ts`) and outside it.
- `@wcstack/state`: **`else:` renders again when the `if:` condition is a falsy non-boolean.** `else` is built as the `if` parse result plus an engine-injected `not`, and `apply/applyChangeToIf.ts` coerces the `if` side with `Boolean()`. The `not` registered by `features/formats` threw on a non-boolean, so `if: 0` (also `""`, `undefined`, `null`) rendered **neither** branch and reported only to `console.error`. `not` is now the same lenient `!value` in both the core table and `features/formats`, which also removes the divergence between a page with and without `features/formats` installed. `filterMeta.not.acceptTypes` becomes `"any"`.
- `@wcstack/state`: **a declaration whose feature is missing fails loudly again.** `$watch` / `$scan` / `$stream` / `$recursion` passed silently on a page that installed no features — every hook phase was simply empty — although the README, the design notes and requirement D13 promise `[wcs/feature-not-installed]` when the state is defined. The `_state` setter now gates on the declaration keys (after the old-name normalization, so `$streams` hits the same barrier). Related: `core/featureEntries.ts` mapped the key `stream`, while the registered feature name is `streams`, so the barrier would have pointed at the nonexistent entry `@wcstack/state/features/streams`; the dead key `bindComponent` is gone.
- `@wcstack/state`: **`$postUpdate` notifies keyed subscriptions** (`$eq` / `$eqPath` / `$eqIndex`). Keyed subscriptions are deliberately absent from the dependency graph, and `$postUpdate` only walked that graph, so the canonical idiom for an in-place mutation left the previously selected row true (the hole closed in 2.6.0 for `setByAddress`). With no old value to read, the ledger's last observed key stands in for it.
- `@wcstack/state`: **a mounted component's exported getter reaches a planned row again.** The plan fast path for a row's first render (requirement R2) reads the row object once through the proxy and then walks to the leaf with plain property access, which bypasses `getByAddress`'s `readMissing` hook — and an exported key `P.k` is deliberately absent from `getterPaths`, so the "is it a getter" guard did not catch it either. A second, plan-eligible template over a list whose rows mount a component (an `if:` that re-mounts it after the exports are registered, for instance) rendered empty. A leaf key that is absent from the row object now falls back to the ordinary path for that slot; a page with no scope hooks pays one boolean check.
- `@wcstack/state`: **the resolved-filter cache keys on the argument source text as well.** The key used only the typed literals, but a factory consumes both, and `truncate` / `unit` / `join` / `ymd` / `hms` / `padStart` / `padEnd` / `eq` / `ne` read the source text — so `truncate(3,1.0)` returned the answer built for `truncate(3,1)`. The key is also built from the canonical name now, so an old name and its canonical name share one closure instead of two.
- `@wcstack/state`: `Object.prototype` members (`|toString`, `|constructor`, `|valueOf`, `|hasOwnProperty`, `|__proto__`) no longer pass as filters and fail later as "is not a function"; they report `[wcs/filter-unknown]`. The core filter table also carries its own arity, so `|not(1)` is `[wcs/filter-arity]` on a page without `features/formats`, and an unknown filter on a page that installed no formatting filters now names the entry to import.
- `@wcstack/state`: **`class.NAME:` treats `undefined` / `null` as "remove the class"** instead of throwing. A reused row whose object lacked the key took the whole row down with it; `attr.*` already only dropped the attribute (requirement B8).
- `@wcstack/state`: the `:` that separates the two sides of a binding is now found outside quotes, like `;` and `|` (requirement B1). `value|defaults(':'): path` used to throw while parsing.
- `@wcstack/state`: `.state:` / `.state.<key>:` are rejected with `[wcs/binding-syntax]` like the other namespace words. `state.<key>:` is the volume injection namespace (requirement B14③), so the dotted form was ambiguous — and on a `<wcs-state mount=…>` it was silently read as an injection declaration. On any element other than `<wcs-state>`, bind an element property called `state` with the undotted `state:`; on a `<wcs-state>` the whole `state` namespace is reserved for volume injection (see the next entry), so there is no spelling for it there.
- `@wcstack/state`: a binding whose left side names no property is rejected at parse time. `": x"`, `"#ro: x"`, `"|trim: x"` used to create an `element[""]` expando in complete silence, and `"foo.: x"` threw a bare `TypeError` when applied.
- `@wcstack/state`: a left-hand side in the `state` namespace written on a `<wcs-state>` **without** `mount=` reports `[wcs/mount-path-invalid]` instead of failing later as a write to a missing `state` property. One key (`state.taxRate:`) is told to move to a volume element; the bare namespace (`state:`) is told that the name is reserved and to write `state.<key>:`, because telling it to add `mount=` would only lead to "inject one key at a time".
- `@wcstack/state`: **two bindings whose filters differ only in an argument's type no longer share one handler** (requirement B9). `handlerByHandlerKey` is module-global and its key was built from the filters' source text, and `|defaults(0)` and `|defaults('0')` both read as `["0"]` — so the second binding reused a handler that had closed over the *first* binding's filters and wrote a number where a string was declared. Two things were wrong: the key ignored the typed literals, and `bindings/planFilters.ts` dropped `literals` when it resolved the filter implementation, so the typed values never reached the key in the first place. `planFilters` now carries `literals` through, and both places that key on filter arguments — the resolved-filter cache in `core/filterRegistry.ts` and the handler / binding / devtools-declaration keys — go through one shared `filterArgsKey` (source text **and** typed literals), so the two criteria cannot drift apart again.
- `@wcstack/state`: `$resolve` validates the shape of its arguments with the same vocabulary as `$getAll` / `$setAll` (`$resolve("a")` raised a bare `TypeError`), and rejects a fourth argument instead of dropping it.
- `@wcstack/state`: `delete state.x` and `Object.defineProperty(state, …)` are refused on a readonly proxy (requirement B6). Deleting through a readonly proxy actually removed the branch, and the next read then threw `[wcs/binding-path-missing]`.
- `@wcstack/state`: a state source that is not an object (`JSON.parse("null")` from `src=`, a number, a string) is named as such instead of raising `Cannot use 'in' operator … in null`, and a frozen state that still uses an old declaration key reports `[wcs/declaration-alias]` rather than `object is not extensible`.
- `@wcstack/state`: an attribute binding compares the stringified value, so a numeric or boolean value no longer runs `setAttribute` on every update (`applyChangeToText` already normalized).
- `@wcstack/state`: a `for` template with no bindings at all is no longer compiled into a row plan — the row ledger keyed on slot bindings could not release such a row, and `destroyRow` fell back to destroying every row of the shared session.
- `@wcstack/state`: `registerFilters` cleans up old names the same way it cleans up arity (it only ever added them), and `getRecord` (an inspection-only accessor) hands out ids that cannot collide between rows.
- `@wcstack/state`: **a deep partial mount no longer makes the component's sibling keys public.** "An explicit partial mount wins over an own key" (requirement B14②) is about one segment (`state.theme: theme`), but the runtime registered the first segment of an entry of any depth — so `state.a.b: outer.b` took the privacy of `a` away wholesale and `a.c` silently read the host's `outer.a.c` (or threw `does not resolve` on a mount with no root entry). Only a one-segment entry marks a key as mapped now.
- `@wcstack/state`: **a component's own method wins over a partial mount of the same name again.** With `state.save: x` on the host, `this.save` translated to the tree path and the author's `save()` became uncallable — a reversal introduced with B14②, which was about a data key's default value, not about methods. A partial entry that the component's own surface hides (an accessor, a method, or the first segment of a deep entry over an own data key) is now reported once as `[wcs/mount-own-key-shadow]`; a volume raises on the same collision (D30).
- `@wcstack/state`: **a volume's `$renderedCallback` names an injected path by longest match.** `relativeVolumePath` (the inverse of D33's translation) took the first injection in declaration order, so with `state.a: settings; state.b: settings.tax` an update of `settings.tax` arrived as `a.tax` while a read of the same path resolved through `b` — the answer depended on the order the injections were written in. The mount path itself takes part in the match too, and `readVolumeInjections` returns its entries sorted the way `findMountEntry` documents.
- `@wcstack/state`: **`this.$x = …` in a volume no longer creates a junk tree key.** The volume chroot's `set` trap translated `$`-prefixed names, so `this.$foo = 1` wrote `cart.$foo`; the `get` trap and a component's chroot both leave the reserved namespace to the parent. It now does too.
- `@wcstack/state`: **`$eq` / `$eqPath` / `$eqIndex` / `$dependOn` resolve against the scope they are called in.** A mounted component's chroot and a volume's chroot translated `$getAll` / `$setAll` / `$resolve` / `$postUpdate` but passed the keyed-selection calls (3.0) and `$dependOn` (3.2) straight through, so inside `<wcs-state mount="cart">` or a `bind-component` scope they read the **root's** path: `this.$eq("selectedId", 2)` compared against the root's `selectedId` and returned `false` where `this.selectedId` was 2, or threw `[wcs/binding-path-missing]` naming a path the author never wrote when the root had no such key; `this.$dependOn("subtotal")` recorded the edge on the root. All three chroots now read one table (`webComponent/dollarPathApis.ts`, guarded against `proxy/traps/get.ts` by a test) — `$eqPath` translates **both** of its paths, `$eq`'s key and `$eqIndex`'s level are left alone, and `$untracked` / `$untrackDependency` take a callback so they stay untouched. Contract: state README (Keyed selection), docs/state-mount-design.md §4-6. **Meaning changes** for a scope that called one of these with a path that exists at the root: it now reads the scope's own path. Reaching the root from inside a scope was never documented, and the previous outcome was either a silent `false` or that throw.
- `@wcstack/state`: **a volume written as a class grafts its prototype accessors.** `splitVolumeState` read own descriptors only, so `class Cart { get total() {…} }` was dropped without a word and `cart.total` stayed undefined; the `**`-getter check next to it already walked the prototype chain. Both it and the D30 collision check (an injected key declared as an accessor or a method) now use `getAllPropertyDescriptors`, which stops before `Object.prototype` and lets the nearest declaration win, so an own data key still shadows a prototype getter. Prototype methods and `constructor` are filtered out as before. That raise and the injection diagnostics that came from the binding parser (`state.a: tree.**.x`) now carry `[wcs/mount-path-invalid]` and name the element and its `mount=`.
- `@wcstack/state`: **a mounted component written as a class keeps its prototype accessors too.** `collectAccessorKeys` was the last place still reading own descriptors only, so for `class Card { get total() {…} }` bound with `bind-component` the key was absent from `getterKeys`: rule 1 never fired, `total` was translated to the **host tree** (`cards.*.total`) instead of the component's marker path, `exportIndex` could not publish it, and the "is this a method" probe in `isPrivateAnchor` re-ran the getter on every translation. `components/State.ts` (`getterPaths`) and `dcc/defineDCC.ts` already walked the prototype chain, so the same object described itself two different ways. It now uses `getAllPropertyDescriptors` like the rest, and the getter is evaluated zero times while paths are translated. **A class-based component changes meaning** if it declared a getter whose name also exists on the host tree under the mount point: the getter now wins inside the component, as it already did for a state written as an object literal (the host side still reads the tree — exports only answer keys the tree does not have).
- `@wcstack/state`: **a `<wcs-state mount=…>` inside a `[data-wc-definition]` host lands as a volume** when neither feature is installed. The DCC barrier ran first and failed the element as the owner of the tree, marking a root node that has no root yet as unavailable and taking sibling volumes down with it — the landing requirement D23 introduced for volumes. Both barriers point at `@wcstack/state/features/scopes`, so only the landing changes.
- `@wcstack/state`: **a feature installed after `bootstrapState()` now defines its tags anyway.** `registerComponentDefiner` only pushed onto an array and `registerComponents` had already run, so `installFeatures([ssr])` in the reverse order left `<wcs-ssr>` undefined — with no `[wcs/feature-not-installed]` to show for it, because the readiness barrier gates declarations, not tags. A definer that arrives late is now applied to the registries that were already bootstrapped (definers guard with `registry.get`, so this cannot double-define). The README states the intended order as well.
- `@wcstack/state`: **a getter that derives from a keyed getter (`$eq` / `$eqPath` / `$eqIndex`) no longer goes stale.** The keyed notification enqueued the subscriber's own address but, unlike an ordinary write, never walked that address's dependents — so `get label() { return this.picked; }` over `get picked() { return this.$eq("sel", …); }` kept its old value while `picked` itself updated correctly. It reproduced on a plain tree with no mounts, and a mounted component's **exported** getter was the same hole wearing a different face (the export alias is a dynamic-dependency edge), which the scope-relative `$eq` fix made observable for the first time. The subscribers are still collected **before** the write (the old key is what finds the row that was selected until now), but the dependency walk from each of them now runs **after** it, where `notifyWrite` already walks — walking before would expand lists from the pre-write value. `$postUpdate` (`notifyKeyedPostUpdate`) had the same hole and is fixed with it. Keyed selection keeps its reason for existing: the walk starts from the subscribers, not from the written path, so a swap stays O(subscribers) — measured at 10,000 rows, a selection change still re-evaluates ~2 getters and costs about 2 µs more than before, while a write with no keyed subscription at all is unchanged. The two enqueue paths driven by a **list diff** — `moveIndexWatchers` (innermost `$eqIndex` level) and `rekeyIndexSubscriptions` (outer levels) — had the same hole and are fixed with them: deleting a row used to leave a getter derived from an `$eqIndex` getter showing the previous row's value. A diff site has no state proxy (it is reached from `createListDiff`, both inside and outside a dependency walk), so it pushes the subscriber's address onto a per-tree buffer and the dependency walk — which has the proxy, the dependency tables and the visited set — drains it at its end; the push sites sit behind the same "any keyed subscription registered?" guard as the rest, so a page without `$eq` never reaches them. Cause, repro, measurements and the mutation results are in [docs/state-keyed-derived-propagation.md](./docs/state-keyed-derived-propagation.md).
- `@wcstack/state`: **retiring a parent row of a nested list no longer leaks its children's keyed subscriptions or `$eqIndex` watchers.** `dropKeyedSubscriptionsByListIndex` is only called for a list's own `deleteIndexSet` and `IListIndex` has no downward link, so replacing `groups` never dropped the subscriptions of `groups.*.rows.*`: rendering stayed correct (the updater discards dead addresses) but the entries were retained, and the devtools pull API reported `rows 20` for a four-row page — the worst failure mode for a feature that exists to show that number. A row with keyed subscriptions is now indexed under each of its ancestor rows (once per row, on its first subscription, walking the strong `parentListIndex` chain), so retiring a parent drops the whole subtree with one lookup; an `$eqIndex` list watcher is indexed under the row that owns its list, which `moveIndexWatchers` could only move between `indexes` arrays, never release. Both indexes are `WeakMap`s, and a page that uses no keyed selection never reaches either.
- `@wcstack/devtools`: **the Overlays section shows a mount's exported getter paths.** `IMountOverlaySummary.exports` has been in the hook protocol — and emitted by `@wcstack/state` — since overlay exports landed, and `docs/devtools-hook-protocol.md` §3 prescribes reading it as `summary.exports ?? []`, but the consumer-side `IMountOverlaySummaryLike` never declared the field and the overlay row never drew it. Since exports are what a mounted component publishes to its parent scope, the one surface that makes the overlay address space visible was missing half of it. A runtime without the field (an older v2 state) still renders the row, now without an `exports:` entry.
- `@wcstack/devtools`: the declared-filter type of the hook protocol declares `literals` (`IDeclaredFilterLike`, matching the runtime's `IDeclaredFilter`). The filter key is built from `literals ?? args` (requirement B9), so a consumer that implemented `IDevtoolsSourceLike` against the previous `{ filterName, args }` shape type-checked while silently degenerating the key — `"1"` and `1` collapsing onto one entry. Both language versions of `docs/devtools-hook-protocol.md` carry the field too.
- `@wcstack/state`: **`date` / `time` / `datetime` accept their locale argument again.** The implementation has read `options[0]` since 2.x, but the arity table (and `filterMeta`, which lint and the VS Code extension read) declared `[0, 0]`, so the form the README prescribes — `createdAt|date(ja-JP)`, `createdAt|datetime(en-US)` — threw `[wcs/filter-arity] … accepts at most 0 argument(s)` at binding-plan time from 3.0 on, and the editor flagged it as an error. 2.6.1 had no arity check at all, so this was a compatibility break introduced by B7. The bounds are now `[0, 1]`, the same shape as `locale`.
- `@wcstack/state`: **`substr` reports its missing length as an argument count.** The arity table said `[1, 2]` while the implementation requires both arguments, so `substr(0)` slipped past the check and failed inside the factory with "filter substr requires at least one option" — a message that carries no `[wcs/…]` code (invisible to lint and to the extension) and states the wrong bound. It is `[2, 2]` now, in the arity table and in `filterMeta`.
- `@wcstack/state`: **`eq` / `ne` stop throwing when a numeric value meets a typed `true` / `false` / `null`** (requirement B9). The numeric branch ignored the typed literal and forced the option through `Number()`, so `selectedId|eq(null)` — which the README documents as matching `null` — threw `filter eq requires a number as option` **on every apply** the moment the id became a number, taking that binding down with it. A non-string literal now compares as itself (a number is never equal to `null` or `true`). An unquoted non-number such as `eq(abc)` still reports the type mismatch, and that check stays inside the closure on purpose: `eq` accepts values of any type, so `status|eq(active)` cannot be judged before the value is known.
- `@wcstack/state`: **a formatting filter no longer paints the word "undefined" into the page.** The display-side empty-value rule (requirement B8) is applied to the value *after* the filters, so anything building its result with `String(value)` undid it: `attr.title: x|trim` wrote `title="undefined"` where the unfiltered `attr.title: x` removes the attribute, and `textContent: x|upper` rendered `UNDEFINED`. `upper` / `lower` / `capitalize` / `trim` / `slice` / `substr` / `padStart` / `padEnd` / `repeat` / `reverse` / `truncate` now pass `undefined` / `null` through, as `unit` already did, and the apply side empties the text and removes the attribute as it does without a filter. Unchanged on purpose: the filters for which an absent value *is* the input (`defaults` / `coalesce` / `nullIfEmpty` / `boolean` / `truthy` / `falsy` / `not` / `eq` / `ne`), the conversions (`int` / `float` / `number` / `string`), and the type-checking number / date / array families — their throw is confined to the one binding and reported through `$errorCallback`, which is a different quality of failure from silently writing "undefined".
- `@wcstack/state`: **SSR output no longer drops a falsy non-string from `textContent` / `innerText`.** The raw value was assigned and the IDL left to stringify it, which is correct in a browser but not under happy-dom, whose setter discards `0` and `false` — so `textContent: count` rendered empty in the server HTML while the hydration props carried the right value, and only the no-JS / SEO / first-paint view was wrong. Both properties are now coerced the way their IDL does (`textContent` is a nullable `DOMString`, `innerText` is `[LegacyNullToEmptyString]`, so `null` is the empty string), which also makes the same-value guard compare strings instead of rewriting on every update. `innerHTML` is deliberately left alone so a `TrustedHTML` value is not flattened into a plain string.
- `@wcstack/state`: `builtinFilterFn` (the tooling-only factory lookup) reads own keys only, closing the same `Object.prototype` hole the filter registry closed with a `Map`: `builtinFilterFn("toString", [])` returned `"[object Undefined]"` and `"valueOf"` failed as a bare `TypeError` instead of reporting `[wcs/filter-unknown]`.
- `@wcstack/state` / `@wcstack/server`: **a volume that loads from an inline `<script type="module">` no longer hangs the render — and no longer poisons the whole server process.** `_loadStateFromSource` looks up `script[type="module"]` synchronously, before its first `await`. The root path gets a microtask boundary ahead of that from `connectedCallback`'s `await runPreparing(...)`, so a mid-parse upgrade still sees the child script; a volume returns earlier (the `runConnecting` claim) and had no boundary, so the script looked absent, the load fell into the "waiting for an API set" branch, and `connectedCallbackPromise` stayed pending forever. In `renderToString` that meant `waitForReady` never returned, the `finally` that releases `renderMutex` was never reached, and **every later render on that process hung too** (measured: one broken page, then a healthy page pending forever). `volumeLifecycle.ts` now takes the same boundary before loading. `mount="v" json='…'` and a root inline script were never affected. Regression tests on both sides (`__tests__/integration.volumeInlineScript.test.ts`, `packages/server/__tests__/render.test.ts`).
- `@wcstack/server`: **`renderToString` has a deadline** (`RenderOptions.timeoutMs`, default 30,000 ms; `0` disables). Independently of the cause above, a page that never becomes ready used to hold `renderMutex` forever, so one bad page killed the process. The limit rejects with a message naming the cause, and the `finally` — including the best-effort `getBindingsReady` drain, which is bounded too — releases the mutex so later renders still work. Long-running legitimate pages are unaffected at the default.
- `@wcstack/state`: `bridge/featureBridge.ts` freezes the shared empty array it returns when no scope feature is installed; a caller that pushed to it would have leaked those entries into every later tree. `registerComponents` holds bootstrapped registries through `WeakRef` instead of a strong `Set` and skips duplicates — a page that creates a scoped `CustomElementRegistry` per tree (and, with the Phase 2 of the scoped-registry design, per DCC instance) used to pin every registry and every constructor defined in it for the life of the page.
- `@wcstack/server`: **`renderMutex` can no longer leak through the second door.** The deadline above lives inside `renderToString`'s `try`, but `new Window({ url })` and `installGlobals()` ran *before* it — so an invalid `url` (an origin-less `"/products/1"`, say) threw `TypeError: Invalid URL` while holding the mutex, and **every later render on the process hung forever** (measured). Window creation, the globals swap and the whole cleanup now sit inside a helper, and `renderToString` holds only `try { … } finally { releaseMutex(); }` around it, so no statement between `acquire()` and the release can throw past the `finally`. The three cleanup steps (`restoreBaseUrl` / `restoreGlobals` / `window.close()`) are each guarded too — one failing step no longer skips the others and leaves the globals swapped for the next render.
- `@wcstack/server`: **a `timeoutMs` above 2 147 483 647 — `Infinity` included — no longer inverts into an immediate timeout.** Node rounds such a delay down to 1 ms, so "raising the limit", exactly as the timeout message suggests, made a healthy page reject in ~13 ms (measured). `normalizeRenderTimeout` folds anything unusable (`NaN`, `≤ 0`, over the ceiling) to "no limit", and the new `MAX_RENDER_TIMEOUT_MS` / `CLEANUP_MIN_TIMEOUT_MS` constants are exported. The readiness wait and the cleanup drain now **share one budget** (the drain gets what is left, floored at 1 s) instead of each taking a full `timeoutMs`, so the worst-case wall time is `timeoutMs + 1 s` rather than twice the limit, matching what the option documents. `RenderOptions.timeoutMs` is now documented in the server README (en/ja), which it was not.
- Benchmarks: **the NOTE added in 3.x to protect the benchmark fixture was breaking the very substitution it described.** It spelled the marker literal `this.$untrackDependency(() => this.selectedIndex)` verbatim, above the getter, so the fixture contained it twice — and the six measurement scripts use `String.replace` with a short literal, which replaces only the first match. The comment was rewritten, and every one of those scripts now keeps the marker in one `MARKER` constant and checks that **the getter actually changed** (`html.includes(MARKER)`) rather than merely that something did; the old `html === original` guard passed happily while the `natural` / `tracked` variants were byte-identical to `manual`, silently voiding the A/B comparison.
- `@wcstack/state`: **an SSR snapshot no longer carries another request's templates.** `Ssr.buildContent` serialized **every** uuid in `structural/fragmentInfoByUUID`, a module-lifetime `Map` with no delete, so a server process that renders more than one page put the previous page's structural templates into the next page's `<wcs-ssr>` — measured as 2 → 12 templates over four renders of the same page, with page A's `for: secretItems` rows appearing in page B's HTML. The snapshot now carries only the fragments reachable from **this** document's placeholder comments, walking into each fragment so nested templates (including the ones inside an `if` branch that never rendered) still come along. uuids are monotonic and never reused, so reachability is an exact ownership test.
- `@wcstack/state`: **an SSR snapshot no longer carries another request's hydration props.** `clearSsrPropertyStore()` ran only at the end of `Ssr.buildContent`, so rendering a page with no `enable-ssr` left the strongly-referenced `Set<Node>` in place and the next page's props JSON carried the previous page's values (measured: `{"wcs-ssr-0":{"valueAsNumber":"PRIVATE-C"}}` on a page that declared no such binding). Two changes close it: `buildContent` writes only props of nodes still connected to this document, and `buildSsrDocument` clears the store even when it generated no snapshot at all. `resetSsrRenderState()` is exported for a server that wants to drop both ledgers between renders.
- `@wcstack/state`: **`{{ }}` inside a `for` / `if` template survives SSR.** Template registration rewrites a text-binding comment into an empty text node (a row-instantiation optimisation), and the snapshot serialized that fragment as markup — so the binding was simply absent from `<wcs-ssr>`, and after hydration the row's text was empty **permanently** (`<li>row {{ .n }}!</li>` hydrated to `row !` and never recovered, while the server-rendered body was correct). The snapshot now restores the original comment on the serialized clone (never on the live fragment). Hydration had a second hole in the same path: `Ssr.restoreTextBindings` ran **after** the SSR blocks were collected, so a row's `{{ }}` was still a `@@wcs-text-start/end` pair when the row's bindings were gathered — and restoring afterwards discarded the server-rendered text with nothing bound to write it back. It now runs first, and a genuine text-binding comment is no longer excluded from the block's initial apply (a structural placeholder that failed to restore still is).
- `@wcstack/state`: **hydration is linear in the number of hydration props again.** Each entry ran its own `root.querySelector('[data-wcs-ssr-id="…"]')`; the index is now built once. Measured over 800 / 1600 / 3200 `textContent` rows: 109 / 297 / 1207 ms before, 45 / 55 / 108 ms after — matching the `value` control (no props) at 27 / 35 / 73 ms, where 3200 rows used to make SSR hydration far slower than plain client rendering.
- `@wcstack/state`: hydration removes `data-wcs-ssr-id` when it succeeds, as the version-mismatch fallback (`Ssr.cleanupDom`) already did; the successful path left the server's bookkeeping attribute in the live DOM.
- `@wcstack/state`: **hydration wires a deferred `spread` again.** `hydrateBindings` dropped the third element of `collectNodesAndBindingInfos` (the `...: path` entries whose custom element is not defined yet), so on an SSR page such a binding was never scheduled on `whenDefined` and stayed unwired forever — the ordinary path schedules it. Both the document pass and the per-block pass now call the same `scheduleDeferredSpreads`, with the row's loop context where there is one.
- `@wcstack/state` / `@wcstack/server`: **a long-lived rendering process no longer grows one render at a time.** The structural-template registry is module-scoped with no delete, so it accumulated every page the process ever rendered. The ssr-snapshot protocol gains an optional `reset()` that the renderer calls as the very last cleanup step — after the window is closed, because the readiness drain just above it may still be finishing bindings that read those registries. It rides the protocol rather than a package import for the same reason `build()` does: the global symbol pins it to the copy of state that actually ran, whereas importing a split entry would load a second core and clear the wrong ledgers. Additive in both directions — an older renderer just keeps memory longer, and an older provider is skipped with `reset?.()`. Output was never at risk: each snapshot is scoped to its own document.

### Changed

- `@wcstack/state`: syntax errors that had no code carry `[wcs/binding-syntax]` and the lint hint — a missing `:`, an unmatched parenthesis in a filter, and the two spread errors. The VS Code extension only turns messages carrying that code into diagnostics, so these never reached the editor. The empty-filter message quotes the original text instead of rebuilding it from the split parts (`textContent: a|` used to report an empty string), and a modifier swallowed by a filter name (`value|trim#ro:`) is now reported as a misplaced modifier instead of `[wcs/filter-unknown] filter not found: trim#ro`.
- `@wcstack/state`: the manifest gains `declarationAliases` and `apiAliases`, so a consumer can tell that `$streams` / `$updatedCallback` / `$trackDependency` are reserved old names — each maps to its canonical name (`$stream` / `$renderedCallback` / `$dependOn`), which is what `reservedLifecycle` / `reservedStateApi` list. `WCS_MANIFEST_VERSION` goes to `2`. `builtinFilterAliases` is re-exported from the package root, matching `builtinFilterMeta`.
- `@wcstack/state`: `[wcs/declaration-alias]` messages carry the lint hint, and `filterMeta` descriptions state each filter's default argument (`padStart` pads with `0`, `padEnd` with a space — deliberately not symmetric).
- `@wcstack/state`: `filterMeta.truncate` states the real default suffix (`…`, one U+2026 character — the description said three ASCII dots, and `filterMeta` is what the VS Code extension shows in completion and hover), and `date` / `time` / `datetime` describe their optional locale argument. The state README documents both defaults, says the date filters take a `Date` rather than a timestamp, and describes how the empty-value contract interacts with filters.
- `@wcstack/state`: the dead error helpers `valueMustBeString` / `valueMustBeBoolean` are gone — nothing has referenced them since `not` became truthiness-based, and the only thing keeping them alive was a test written against them. The numeric option handling shared by twenty-odd filters is folded into one pair of helpers, which also moves the `Number()` conversion off the per-apply path.
- Docs: the 3.2 alias table in the migration guide now describes what normalizing a declaration key actually does. The old name is **copied** onto the canonical one and then deleted **only if it was an own property** — so an object-literal state loses it, while a `class` state keeps it (the declaration is on the prototype and only the copy lands on the instance). Either way, state code that reads its own declaration back should read the canonical name; on an object-literal state it must. What keeps working through 3.x is *declaring* with the old name, not reading the declaration back. Behaviour is unchanged since 3.2 — only the contract was undocumented, and the previous note overstated it by saying the old name always disappears.
- `@wcstack/state` README: the filter-argument section documents the quoting rules (no escape character, adjacent quoted runs concatenate, trailing empty argument dropped), and the empty-value contract now lists `class.*` alongside the other display surfaces — with the difference spelled out: only `undefined` / `null` take the class off, and any other non-boolean still throws (write `|truthy` to coerce).
- `@wcstack/state`: `@wcstack/state/parser` exports `indexOfOutsideQuotes` and `splitOutsideQuotes`, the canonical quote-aware scan and split for the binding syntax. Positional tooling had to hand-copy them, which is exactly how a tool drifts from the runtime. (The runtime itself was not fully on them: the `for` row shorthand expander still scanned `;` / `:` / `|` raw — see the fix below.)
- Docs: the v2 → v3 migration guide covers what 3.1 and 3.2 add, for a page upgrading straight from 2.x.
- `@wcstack/state`: **a split entry no longer carries another feature.** One static import across the seam pulls the whole of the other feature into a shared chunk: `features/scopes` reached `watch/watchRuntime` for a volume's `$watch` and took 5.3 KB gzip of the temporal runtime with it, and `features/devtools` reached `webComponent/mount.ts` for `overlays()` and took 3.3 KB gzip of the scope machinery. Both calls now go through receptacles in `src/bridge/`, which the owning feature fills on install. Measured on the split build: `features/scopes` 19,697 → 13,991 B gzip of its own, `features/devtools` 5,364 → 2,173 B, `features/temporal` 10,572 → 9,672 B. The full bundle and `/auto` are unchanged in behaviour. A volume that declares `$watch` on a page without `features/temporal` now reports `[wcs/feature-not-installed]` instead of working by accident (a volume's state does not pass through the `_state` setter that gates the other declarations).
- `@wcstack/state`: a mount with no `#ro` entry — the overwhelming majority — skips the read-only lookup on every write instead of paying a `split(".")` and a longest-prefix scan, and the `ro` modifier a read-only mount adds to a translated binding is only added to the kinds that read it (`prop` / `radio` / `checkbox`); `for` / `if` / `elseif` reject modifiers when parsed, so the runtime no longer builds a binding the parser could not.
- `@wcstack/devtools`: `IMountOverlaySummaryLike`, `IKeyedSubscriptionSummaryLike`, `IDeclaredBindingLike` and `IDeclaredFilterLike` are exported by name from the package root. They were declared in `dist/index.d.ts` but unreachable, so an adopter implementing `IDevtoolsSourceLike` in TypeScript had to hand-copy the return shapes of `overlays()` / `keyedSubscriptions()` / `getDeclaredBindings()` — which is exactly how a hand-written structural type drifts.
- `wcstack` (entry package README — the guide `npm view wcstack readme` serves to AI agents): the Properties table carries the 3.1 explicit-property form `.NAME`, with the trap it exists for spelled out (`online: x` subscribes to a `"line"` event and never writes the element's `online` property). Also added: `#sync=` in the Modifiers table beside the full `#init=` value list, the 3.1 volume injection `state.<key>:` under a short `mount=` section, `@wcstack/state`'s split entries (`core` + `installFeatures`, and why never through `esm.run`) in the loading section, and a "Names that changed in 3.2" table for the ten filter aliases, `$stream`, `$renderedCallback`, `$dependOn` and `$untracked` — the old names are what the training data holds, and lint only flags them at info severity.
- `wcstack` README: "exit code 0 = clean" is corrected in both places it appeared. `@wcstack/lint` exits `0` whenever there is no **error**-severity finding, so warnings and info diagnostics (an old name, an unresolved path) print and still exit `0`; `--strict` is named as the way to fail on warnings too. A generate-validate-fix loop that stops at exit `0` was being told it had a clean file.

### Removed

- `@wcstack/state`: `recursion/generation.ts` no longer sweeps the evaluation cache when a re-set forgets the previous generation's `**` accessors. The sweep was added before the cache carried a **generation stamp**; now that both cache write sites stamp `stateElement.stateGeneration` and only same-generation entries can hit, and `forgetGeneration` runs from `runPreCommit` — immediately before `_stateGeneration++` — every entry it deleted was already a guaranteed miss. ## [3.0.0] — 2026-09-22

**3.0 reads a binding as written, or refuses it by name — and the core of `@wcstack/state` is split from its features.** The changes are in `@wcstack/state` and its tooling; every other package moves to 3.0.0 only to keep the lockstep version. There is no compatibility layer: 2.6 announced every form that changes here as `wcs/v3-migration`, so upgrade to 2.6.1, clear those warnings, then move to 3.0. ### Added

- `@wcstack/state`: **split entries.** `@wcstack/state/core` holds the binding engine; `@wcstack/state/features/{temporal,scopes,recursion,ssr,formats,devtools,diagnostics}` add `$watch` / `$scan` / `$streams`, `bind-component` / `mount=` / DCC, `$recursion`, SSR, the formatting filters, the DevTools source and the development-time path warnings, installed with `installFeatures([...])`. Every entry shares one core chunk. A declaration whose feature is missing throws `[wcs/feature-not-installed]`, naming the entry to import. `@wcstack/state/define` gives `defineState` and the types with no runtime. `@wcstack/state` and `/auto` still install every feature, so existing pages load and behave as before. ## [2.6.1] — 2026-09-21

### Fixed

- `@wcstack/state`: keyed selection (`$eq` / `$eqPath` / `$eqIndex`) could leave a row selected, or never select it, without an error:
  - **Object keys.** Writing an object to `path` (`this.selected = row` for `$eq("selected", this["items.*"])`) did not re-evaluate the previously selected row, so two rows showed as selected. An object write skips the same-value guard, which was the only source of the old key; the rows are now keyed by the value they last saw. The same applied to any write with `config.sameValueGuard` off.
  - **Replacing an object above `path`.** `this.sel = { id: 2 }` for `$eq("sel.id", …)` re-evaluated no row, and a later write to `sel.id` left the stale row selected. Such a write now re-evaluates the rows under the value `path` had in the old object and has in the new one.
  - **A getter `path`.** For `$eq("current.id", …)` with `get current()`, the value changes without a write to `path`, so no row was ever re-evaluated. When `path` is a getter or sits under one, the calls now fall back to an ordinary tracked read. The selection is correct, but every row re-evaluates on a change.

  A key that no row holds any more is also dropped from the ledger, so a removed row object is no longer retained. The state README ("Keyed selection") lists what reaches the rows and notes that keys are not type-converted (`"2"` from an `<input>` does not match the id `2`). The filter and property sections now say what the 3.0 migration table already did: `eq(true)` never matches a boolean in 2.x, and `undefined` leaves the previous text in a reused row.

## [2.6.0] — 2026-09-21

### Added

- `@wcstack/state`: **keyed selection** — `this.$eq(path, key)`, `this.$eqPath(path, keyPath)` and `this.$eqIndex(path, level = 1)`. A row getter that answers "is this row the selected one?" used to depend on the selection path from every row, so one click re-evaluated the whole list (`get "items.*.selected"() { return this.$1 === this.selectedIndex; }`). The keyed forms subscribe each row under its own key, and a write to the path re-evaluates only the row that was selected and the row that becomes selected: selecting one of 10,000 rows goes from 20 ms to 0.2 ms. `$eqPath` keys on an id and survives sorting and removal; `$eqIndex` keys on the row's index, and the list diff re-keys moved rows, so removing a row re-evaluates at most two rows. They subscribe only inside a getter under a list row (elsewhere they return the comparison), a row's subscription is dropped with the row, and keys compare as `Map` keys. Contract: the state README, "Keyed selection".
- `@wcstack/state`: **`wcs/v3-migration` warnings.** 3.0 ships without a compatibility layer, so this release names each form that 3.0 rejects or reads differently — a second `#`, a value after `else:`, modifiers on a structural directive, `radio#ro:`, unterminated quotes and extra filter arguments; unquoted `true` / `false` / `null` in `eq` / `ne` / `defaults` and `0n` through `truthy`; `undefined` reaching `textContent`, an attribute or a style; `$resolve(path, indexes, undefined)`; writes through a readonly proxy or a `#ro` mount; a component default that a partial mount shadows. - `@wcstack/state`: clearing a long list allocates a quarter of what it did. The teardown ran on iterators and grew a per-node `WeakSet` of observer-skip marks; it now runs index loops and keeps one skip count per parent, which moves the young-generation GC out of the clear (clearing 10,000 rows: 8.1 → 2.1 MB allocated, 18–20 ms). ## [2.5.0] — 2026-09-17

### Changed

- `@wcstack/state`: **re-setting an initialized element re-renders the page.** `setInitialState(state)` on a `<wcs-state>` that had already initialized swapped in the new state, and reads returned its values, but no established binding was applied again, so the page kept showing the previous state until a dependent path happened to be written. The re-set now re-applies the established bindings to the new state before `setInitialState()` returns — scalars, getters, row getters, `for` and `if` alike. A binding that cannot be read from the new state reports a failed apply (`console.error`, or the new state's `$errorCallback`). A re-set is not a write: it fires no `$watch` handler and no `$updatedCallback`. Lists are matched by array identity, so pass a new array when a list's length changed; re-setting with the same array instance after pushing to or splicing it in place is not supported. A detached element re-applies when it reconnects, and a view-transition arbiter on the page receives the re-apply the same way it receives an update.
- `@wcstack/state`: `setInitialState()` on a loaded volume (`<wcs-state mount="…">`) now throws. A volume's data is copied into the root tree once, when the volume grafts, so re-setting the volume element changed only that element's own reads and never reached the page — without an error or a warning. Write the paths under the mount path on the root state instead. A volume that failed to graft throws as well.

### Fixed

- `@wcstack/state`: a re-set checks bound paths against the new state. `wcs/binding-path-missing` reports each path once, and that record survived a re-set, so a binding to `user.name` stayed silent when the new state had only `user.nmae`. The record now belongs to one state generation; a `$watch` path that the new state no longer declares is not reported.
- `@wcstack/state`: `setInitialState()` on a detached, initialized `<wcs-state>` no longer throws `State rootNode is not available.` after it has already swapped in the new state (a regression in 2.4.0).
- `@wcstack/state`: after SSR hydration, a getter bound with `data-wcs` inside an `if` block, or inside the rows of a `for` that is not itself inside another block, follows updates. Hydration registered the bindings inside server-rendered blocks without applying them — it applied only the bindings outside those blocks — and a getter records its dependencies only when it is evaluated, so `textContent: items.*.double` kept the server-rendered text when `items.0.n` changed while an aggregate outside the rows did update. Hydration now applies the bindings inside those blocks once, as it does the bindings outside them; the rendered text stays the same. Index bindings (`$1`, `$2`, …) depend on no state and keep their server-rendered text. The inner rows of a nested `for` still hydrate only at the outer level (a known limitation): their bindings are left unapplied rather than reporting a failure on every hydration. Mustache text inside rows, a `for` inside an `if`, and bind-component children inside rows are separate hydration gaps and are unchanged.
- `@wcstack/state`: a `<wcs-state mount="…">` volume that never grafts no longer keeps its mount slot. The slot ledger had no way to release a slot, so a volume detached while its source was still loading, a volume orphaned by a failed root, and a volume whose load or graft failed each held its mount path for as long as the root node lived: a replacement volume on the same path was rejected with `Volume slot "…" is already mounted on this tree.` — an error nothing awaiting the page ever saw — and reloading the page was the only recovery. A volume now releases its slot when it settles without grafting, and when it is detached while loading or while waiting for its root. Such a volume takes the slot back when it is re-attached to the same root, or otherwise just before it grafts, and still grafts as before when the slot is free, even while detached; if another volume took the slot in the meantime, it reports that and does not graft. A release only removes the element's own reservation, so removing a dead volume never frees a slot another volume holds, and reads under the path keep resolving to `undefined`. A grafted volume keeps its slot, and a synchronous throw from a volume's `$connectedCallback` is now reported like an asynchronous one instead of failing a graft whose data was already in the tree.
- `@wcstack/state`: swapping or replacing list rows by writing elements (`this.$resolve("items.*", [0], b)`, `this["items.0"] = c`) keeps the page, reads and writes on the same rows. When a swap completed, the runtime moved each row's identity with its value, but it pinned the written value to the row that used to sit at that position and never re-rendered the list: the row blocks stayed in place with their contents rewritten, `items.0.name` read the other row, a row's `$1` disagreed with the text it showed, a write landed on the other row, and a later array replacement left the page out of step with the array. Replacing a row with a new object this way did not refresh an unbound row getter either (a recursive total showed the old leaf plus the new children). A completed swap now re-renders the list as a replacement of the order before the writes: the row blocks move with their values, together with a row's `$1` and state it holds outside bindings, such as text typed into an unbound input. Writing a value that was not in the list replaces that row in place, so its block and an input being edited in it stay put, and its row getters show the new row.
- `@wcstack/state`: writing to a row and replacing that row in the same batch (`s["items.0.n"] = 5; s.items = [{ n: 9 }, s.items[1]]`) shows the new row. The row's binding, queued by the first write, was applied for the removed row; the list then reused that row's pooled content for the new row and skipped the binding as already applied, so the page showed `5` while the state held `9`.

## [2.4.0] — 2026-09-15

### Added

- `@wcstack/state`: **`$scan`** declares an accumulation that outlives a stream run. `$streams` folds within one run and resets to `initial` on every restart, and `$watch` owns no value, so a feed built across page runs had to be concatenated by hand inside a handler. `$scan: { feed: { from: "pageResult", initial, fold } }` gives that value an owner. The runtime folds each landing of a state path once per update batch (`from`, folded and written before `$watch` in the same drain, so a `$watch` handler reads the folded output and a value it writes stays; a `$watch` on the output normally gets `prev` undefined, but when the source is written again before the output's landing drains — by a `$watch` handler in that drain, say — it gets the landed value in `prev`, sees `cur` one step ahead and can fire again with the same value, so such a handler should tolerate a repeated value), or each event of a declared event token synchronously (`on`, before that token's `$on` handlers), and keeps the output across restarts, disconnects and re-sets of the same object (also when the fold returns functions). Plain data in `initial` (arrays and plain objects made of enumerable data properties) is copied onto the output — on materialization and on every reset — so writing a child path in that plain part never changes the declaration (class instances, frozen values and other non-plain values stay shared with it), and a reset writes nothing when the output already has the value of `initial`. A scan that folds another scan's output reads it as it landed, once per landing, whatever the declaration order. `resetOn: ["host"]` returns the output to `initial` when one of those paths is written: a `from` scan skips the fold of that batch (the reset wins), and an `on` scan folds an event that comes after the write — even one an element dispatches synchronously while the write is applied to its binding — into `initial`, using up the pending reset only once that event's output write succeeds and dropping it when the drain does not fire scans for that batch. The fold is synchronous, receives no `this`, and returning the same `acc` writes nothing; a throw, a returned Promise or a value that cannot be read is reported to the console and DevTools and writes nothing — an unreadable row of a wildcard `from` is skipped alone, and row landings are narrowed to one per list position, so a row written and then replaced or dropped in the same job is neither folded twice nor read out of range. An output that collides with a getter, a setter, a method or a `$streams` entry, a getter as `from` or `resetOn` (or a path under one, including an expansion of a `$recursion` `**` getter such as `nodes.*.total` as `from`), a setter without a getter as `from`, a `from` that reads its own output, a `resetOn` path under the entry's own `from`, scans that feed each other and malformed entries raise at declaration (`wcs/scan-declaration-invalid`, `wcs/scan-source-computed`) before the generation advances. A stream whose `args` derive from its own scan output — directly or through another scan that folds it — raises `wcs/scan-feedback-loop`, and a chunk that lands in the same batch as its stream's restart is not folded. `$scan` is root-only: a volume refuses it, and a mounted component gets the `wcs/mount-dollar-declaration` notice. The runtime folds once per landing, not once per page, so keep an idempotency key when a page can land twice (a retry after `done`, or reconnecting the page). `examples/state-intersect-scroll` now accumulates its feed with `$scan`. Design: [docs/state-scan-design.md](./docs/state-scan-design.md); reference: [packages/state/docs/scan.md](./packages/state/docs/scan.md). ([#272](https://github.com/wcstack/wcstack/issues/272))
- `@wcstack/lint`: `wcs-validate` checks `$scan` declarations under the runtime's codes — `wcs/scan-declaration-invalid` and `wcs/scan-source-computed` (errors) for the shapes the runtime rejects (including scans that feed each other through `from`, an output that collides with a method, an empty output name, an entry written as an array, a `from` that is an expansion of a `$recursion` `**` getter, a `from` that is a setter without a getter, and a `from` / `on` / `resetOn` entry that is not a string; a `**` in `from` / `resetOn` is `wcs/recursion-unsupported`, as at runtime; `$scan: []` and a `$scan` declared in a volume are errors, and one in a mounted component is a warning), and `wcs/scan-path-missing` (warning) for a `from` / `resetOn` path the state does not declare (a `$recursion` expansion counts as declared, as for `$watch`). Scan outputs materialize as path candidates from `initial`, like `$streams` values.
- `@wcstack/devtools`: `state:watch-error` accepts `phase: "fold"` and `phase: "write"` for `$scan` (a fold, and an output write; a value a scan could not read reuses `"evaluate"`), reported with the path `$scan.<output>`, and `state:path-unresolved` accepts `source: "scan"`.

### Fixed

- `@wcstack/state`: replacing row objects while keeping their `children` arrays — `this.nodes = this.nodes.map(n => ({ ...n }))`, the ordinary immutable update — no longer leaves that row's aggregate stale. The child list's rows hung under the row object that was just retired, so a later leaf write dirtied the **retired** row's address while the rendered binding watched the **live** one: the leaf, the deeper totals and every `[]` union stayed right, and only the row's own `nodes.*.total` froze, with no diagnostic. Rows are now repaired instead of rebuilt — when the parent a list's rows hang under has been retired, those same row objects are re-pointed at the live row, so anything keyed by row identity survives the update — a `bind-component` child scope keeps its rendered rows, and any row state you never bound there (an open `<details>`, focus, a JS marker) with them; rebuilding the rows instead was measured to destroy all four of them. A plain nested `for` still rebuilds the child rows under a replaced parent row, here and on 2.3.0 alike. Sharing one `children` array between two rows is a separate thing. While both rows are in the list it is unchanged: an array has exactly one set of rows, so both rows always agree on every value, and a row getter that reads its parent is evaluated in the context of the row that owns those rows — the one that first expanded the array. What did change is what happens when that owner is removed from the list: the rows follow one of the rows still on screen, so that row's aggregate tracks the shared data instead of freezing at the removed row's numbers — there is still only one set of rows, so with three rows sharing an array only one survivor follows and the others stay frozen, as they do on 2.3.0. Putting the removed row back hands them straight back to it when that row's own object comes back — whether you reassign the same array instance, build a new array holding the same rows, or put the row back at a different position. When every row is rebuilt instead (`this.nodes = this.nodes.map(n => ({ ...n }))`, the update this entry opens with), no row object matches, and the rows end up under whichever row now occupies the owner's old position. Only the same-array-instance restore matches 2.3.0 here; restoring with a new array leaves both rows frozen there, where the returned owner now tracks. Give every node its own array when a child getter reads upward. Pinned in `packages/state/__tests__/integration.sharedListRowRevival.test.ts`, `integration.divergentLedgerReplacement.test.ts`, `integration.recursionKnownDefects.test.ts` (defect 7) and `integration.bindComponentNestedFor.test.ts`. ([#256](https://github.com/wcstack/wcstack/issues/256))
- `@wcstack/state`: an element that fails to initialize no longer hangs the page silently. `connectedCallback` had one unguarded `await`, so a throw from anywhere inside initialization skipped every promise settlement: `connectedCallbackPromise` and `initializePromise` stayed pending forever with no diagnostic — a page that simply never rendered, and a `renderToString()` / `mount()` that never returned. Such a failure is now reported once with `console.error` and rejects `connectedCallbackPromise` with the original error (the declaration's own message, not a wrapper), while `initializePromise` still resolves so one element's mistake does not drag the rest of the page's bindings down with it. It covers everything initialization can throw on a **root** element: every `$` declaration validator, all four state sources, the `enable-ssr` data merge, a DCC or `bind-component` setup error, and the v2 "one `<wcs-state>` per root" rule — where a second root element used to kill the whole page, the first element's page now renders and only the duplicate is refused (that second element stays unregistered but keeps the state it loaded, so remove it; moving a healthy element in the DOM is not a duplicate and is never refused). Detaching an element while its source is still loading is **not** a failure: that connection ends quietly as it always did, and a pooled element that is re-appended initializes, renders, and reports ready. One shape shifts with that repair: when the element is re-appended before its source resolves, `$connectedCallback` and `$streams` now each start exactly once for the live connection, where `main` started `$streams` zero times. Three consequences come with it: `getBindingsReady(root)` rejects for a root whose state element failed instead of reporting "ready" for a page with no bindings; a `<wcs-state mount="…">` volume that was already waiting for that root when it failed settles with its own report instead of waiting forever (that report is the end of the line — an orphaned volume does not re-graft itself when a corrected root is connected later, and its mount slot stays reserved for as long as that root node is alive, so fix the root and reload the page); and `setInitialState()` on an element that already failed throws a diagnostic telling you to replace the element, instead of silently doing nothing. Configuration errors that keep the rest of the page working still **resolve** `connectedCallbackPromise` as before (`name=`, a plain unwired Light DOM `bind-component`, a mount host with no state tree on its root, a mount-scope setup error), and a **volume** never rejects it: its failures resolve it, and some report nothing of their own, leaving the error only as the discarded `connectedCallback` promise. The per-site behaviour is pinned in `packages/state/__tests__/integration.initFailureDiagnostics.test.ts`. ([#257](https://github.com/wcstack/wcstack/issues/257))
- `@wcstack/state`: re-setting a state object (`setInitialState()`, or assigning `_state` again) no longer leaves reads on the previous generation. Two mechanisms were keyed by things that are identical across generations. A wildcard-free getter's absolute address is the same object before and after a re-set, so the cache returned the old value with `dirty:false` — `mount({ items: [1, 2], get sum() { … } })` read `3`, was re-set to `{ items: [5, 6] }`, and still read `3`. And the setter clears `pathSet`, `listPaths` and `elementPaths` while the recursion teardown removes the previous generation's generated edges, with nothing rebuilding them, so a whole-list write after a re-set threw `Cannot expand dynamic dependency with wildcard for non-list address` while the DOM moved on regardless. Cache entries now carry the generation they were written in and a read only hits an entry from the current generation; the generation advances after the previous one is torn down and before the new state object is installed. The path registrations of live bindings are re-derived after the setter's clears, so the ledgers and the static chains are rebuilt for the new generation — clearing `pathSet` stays, because it is the self-heal that restores the static edges the recursion teardown removes. The rebuild exclusion accumulates across generations, where taking it from the previous teardown alone made a second re-set with no read in between re-register static edges for generated paths that were never materialized. `$watch` now reaches its handler after a re-set in a shape where the write used to throw before getting there. Where a throwing `$` declaration validator leaves the element depends on which validator throws: the ones that only inspect the incoming value run before the generation advances, and the ones that need what the setter installs run after it, so there is no single rule and the tests enumerate it one validator at a time. **Two halves of this stay open and are pinned as known holes**: a re-set does not re-apply established bindings, so reads move to the new generation while scalars, wildcard-free getters and `for` rows keep the first generation's text ([#267](https://github.com/wcstack/wcstack/issues/267)), and a re-set on a `<wcs-state mount="…">` volume is a silent no-op for the page, because the graft is a one-time copy ([#268](https://github.com/wcstack/wcstack/issues/268)); and a binding whose path disappears in the second generation is not diagnosed, because the per-path check runs once per element and never looks at the generation ([#270](https://github.com/wcstack/wcstack/issues/270), unchanged from 2.3.0). Hydration is untouched here and stays open as [#258](https://github.com/wcstack/wcstack/issues/258). Pinned in `packages/state/__tests__/integration.stateGenerationReset.test.ts`. ([#258](https://github.com/wcstack/wcstack/issues/258))
- `@wcstack/state`: re-attaching the root `<wcs-state>` — `host.remove(); document.body.appendChild(host)`, or any move of it in the DOM — no longer silently stops `$on` handlers, `on` scans and command-token subscriptions. Disconnecting threw away the command-token and event-token registries, while `$on` subscribes only when the state is set and a `command.<method>:` binding subscribes only when its value is applied, so after reconnecting every element event and every `$command.<name>.emit()` reached a fresh token with no subscribers, with no error and no warning. Disconnecting now keeps both registries, as it already kept the `$streams` and `$watch` registries. Nothing fires while the element is disconnected: an element event finds no state tree, and the state cannot be created to emit a command. A re-set still replaces the `$on` subscriptions. Pinned in `packages/state/__tests__/integration.tokenReconnect.test.ts`. ([#273](https://github.com/wcstack/wcstack/issues/273))
- `@wcstack/state`: a wildcard `$watch` now fires once per row that actually changed, as the list stands when the batch drains. Replacing a nested list with a longer array — `state.$resolve("groups.*.items", [0], [a, b])` over a one-row list — fired only for the positions the old array had: the write's dependency walk read the nested list from the cache before the new array was committed there, saw no change and expanded only the old rows, so the added rows never reached `$watch` while the DOM rendered them. The walk now reads the array it wrote, which also lets a `$resolve` into that nested list right after a structural write succeed where it threw `ListIndexes not found`. A row written and then cut off, removed or replaced in the same job no longer fires either: `$watch` read such a row by index, so shortening or emptying the list reported an evaluation error, and removing or replacing rows fired with the value of whatever row now sat at that position — twice when the row that moved there had changed too, and with the removed row's `prev` when it had not. The address of a row the list diff removed is now dropped and each position fires once; writing an element into `list.*` still fires that position once. `$scan`'s `from` shares the same narrowing. Pinned in `packages/state/__tests__/watch.rowLanding.test.ts`, `scan.from.test.ts` and `integration.recursionKnownDefects.test.ts`. ([#274](https://github.com/wcstack/wcstack/issues/274))

## [2.3.0] — 2026-09-12

### Added

- `@wcstack/state`: **recursive paths** — `$recursion: { "nodes.*": "children.*" }` declares where a tree's shape repeats, and `**` stands for "however deep this is". One getter covers every depth (`get "nodes.**.total"()`, with `this["nodes.**.value"]` and an index-omitted `$getAll("nodes.**.children.*.total")` bound to the depth being evaluated), `$getAll(path, [])` unions every depth (depth-first, pre-order, ascending index), `$setAll(path, [], value)` broadcasts one value to every depth, and each depth's accessor is materialized the first time it is read. `**` never reaches the engine: `PathInfo`, the dependency graph, `$1`…`$n`, `$resolve` and the list diff only ever see ordinary fixed-arity paths, and passing `**` to anything that does not interpret it is `wcs/recursion-unsupported`. This version takes exactly one self-recursive anchor per state, a tree as input (a shared child array is `wcs/recursion-shared-list`, a cycle `wcs/recursion-cycle`), and 128 wildcard levels (`wcs/recursion-depth-exceeded`); rendering a tree stays with a self-referential component. What it refuses, it refuses loudly rather than reinterpreting: at declaration time, recursive setters, a `**` getter that names the structure (`get "nodes.**.children"()`, `.children.*`, `.children.length`) and a concrete getter with the same name as a `**` getter's expansion (`get "nodes.*.children.*.total"()`) — all `wcs/recursion-declaration-invalid` (an anchor or repeating sub-path that carries an index segment, `{ "nodes.0.items.*": … }`, is refused there too — the recursion is declared over the shape of the tree, not over one row), a mis-spelled anchor `wcs/recursion-anchor`; at write time, anything that targets a recursive getter — a recursive `$setAll` on `nodes.**.total`, or a fixed-arity `$setAll`, a `$resolve` with a value or a direct assignment on a concrete expansion such as `nodes.*.children.*.total` / `nodes.1.total` (`wcs/recursion-readonly`, before or after that depth is materialized) — and a recursive `$setAll` that targets the structure (a node, a child list or its `length`, `nodes.**.children.0`; `wcs/recursion-structural-write`), a non-empty prefix on a recursive `$setAll` (`wcs/recursion-setall-form`), and a mapper, `{ spread: true }` or omitted indexes on one (named in the message, and reported by the linter under the same code); a non-array or non-empty `indexes` on a recursive `$getAll` (`wcs/recursion-getall-form`); and `**` handed to anything that does not interpret it — markup, `$watch` / `$listKeys` keys, `$resolve` / `$postUpdate` / `$trackDependency`, an assignment (`wcs/recursion-unsupported`). A bound `**` (`this["nodes.**.value"]`, index-omitted `$getAll`) takes its depth from the innermost evaluation frame only — the same frame the row index comes from — and reports `wcs/recursion-context` elsewhere, including inside a plain getter that a recursive getter calls. `$recursion` and `**` getters are root-only: a volume (`mount=`) is refused before grafting and a mounted component (`bind-component`) gets the `wcs/mount-dollar-declaration` notice. Re-setting the same state object (or one that reuses the same arrays) drops the previous generation's generated accessors with their caches, and a re-set whose new declaration is invalid leaves the element on the previous generation. The editor and `wcs-validate` report every statically decidable form above under the same `wcs/recursion-*` codes, and stay silent where the declaration cannot be read statically (an identifier reference, a spread, a computed key, a `class` state). In TypeScript, `defineState` types every key containing `**` as `any` through a pattern index signature — the VS Code extension's preamble declares the same one, so the editor, `wcs-tsc` and `tsc` agree; ordinary dot paths keep their resolved types. Example: `packages/state/examples/recursive-tree/`; design: [docs/state-recursive-path-design.md](./docs/state-recursive-path-design.md).
- `@wcstack/state`: `wcs/getter-depth-exceeded` and `wcs/index-param-range`. Exceeding the 128-frame address stack was always reported as "possible circular dependency", even for a straight chain with no address visited twice; the two are now told apart by address identity (`wcs/getter-cycle` for a real cycle). `$129`, `$0` and `$01` used to fall through to ordinary property resolution and read as `undefined`; they now throw.

### Changed

- `@wcstack/state`: the list-diff baseline that reads (`$getAll`) and the dependency walk compare against moved from the render path to a state-owned ledger shared by reads, rendering and the walk, committed at the end of each update batch. Until now the baseline was written only when a `for` rendered the list, so a structural write to a list nothing rendered (a sort, an insert, a parent re-assignment) minted a fresh `ListIndex` generation and the child ledgers kept pointing at the old one — aggregates over such lists went permanently stale or threw `ListIndexes not found`. A recursive `$setAll` also commits what it observed, for the same reason; the fixed-arity `$setAll` still does not (`docs/state-set-all-design.md` §6-2).
- `@wcstack/state` SSR: `<wcs-ssr>` snapshots no longer evaluate own enumerable getters of the state object (`{ get count() { … } }` in an object literal). They were evaluated with the raw object as `this`, so a path getter serialized as `null` and a getter calling `$getAll` threw and took the whole page's SSR down. Derived values are recomputed on the client from the same definition; a consumer that read a getter's value out of the snapshot should read the data it derives from instead.
- `@wcstack/state`: `$recursion` joins `$watch` / `$streams` / `$listKeys` as a root-only declaration — a volume (`mount=`) that declares it, or a `**` getter, is refused before grafting, and a mounted component's declaration gets the same `wcs/mount-dollar-declaration` notice as the others.
- `@wcstack/state`: `$getAll(path, indexes)` with an `indexes` that is not an array (`null`, a number, …) now throws a diagnostic that names the argument and the two valid forms, instead of a raw `TypeError: Cannot read properties of null (reading 'length')`. Omitting `indexes` still means "the loop context's indexes".
- `@wcstack/lint`: `wcs-validate` reads a template literal without substitutions as a literal path when it is an API call argument (`` $getAll(`items.*.price`, [0]) ``), the same as a quoted string. Paths written that way are now checked for `wcs/index-arity`, and a `$setAll` / value-carrying `$resolve` written that way now counts as nested-write evidence for `wcs/getter-untracked-read`, so existing pages may see new diagnostics. Template literals with `${…}` stay unchecked.

## [2.2.0] — 2026-09-08

### Docs

- Scoped Custom Element Registries: the gating decision is now stated where adopters look. Phases 0 and 1 shipped in 1.31.0; **phase 2 (per-component local definitions) is deliberately not started until Firefox ships scoped registries** ([bugzilla 1874414](https://bugzilla.mozilla.org/show_bug.cgi?id=1874414)). Its whole value is "the same tag name means different components in different scopes", and a browser without the API degrades not gracefully but by silently binding the wrong component — a buildless, CDN-first stack cannot ship that. Phase 3 is not Firefox-gated. See [docs/scoped-custom-element-registries.md](./docs/scoped-custom-element-registries.md) §2.
- `@wcstack/state` README: an "i18n positioning" paragraph in the Locale section — why there is no i18n package and no live language switch, where the dictionary and the locale live (ES module volume; `<html lang>` and the router `basename`), the cost of `<base href>`, and the two alternatives that were weighed. Until now this lived only in `docs/i18n-design.md` §9.
- `docs/form-tag-design.md`: design note for a `<wcs-form>` I/O node (Constraint Validation API, `FormData` as a state projection, dirty / touched) — the reviewer-identified gap behind hand-written CRUD handlers. Not implemented; the note fixes the shape (rules stay in HTML attributes, results become state, `data-wcs` stays wiring) and lists the six decisions to make first.
- Four README claims corrected against the implementation: route parameters land before `connectedCallback` only for elements that are **already defined** (an undefined one is assigned after `customElements.whenDefined()` resolves, which is after the upgrade, so the upgrade-time `connectedCallback` does not see them); `repeat` overrides `once` only when **positive**, so `<wcs-timer once repeat="0">` stops after one tick; the `<wcs-debounce>` search sample passed the `InputEvent` to `doSearch(q)` because an `oninput:` command emit puts the event first, and now emits `e.target.value` from a state method; the `:state(pending)` CSS sample declared `display: block` and `display: none` on the same selector, so the spinner never appeared (#253).

### Added

- `@wcstack/router`: route guards can now **load data and redirect dynamically**. A guard function receives a third argument — a frozen `{ params, typedParams, searchParams, routeName }` snapshot of the match being entered — and may return, besides `true` / `false`: a **non-empty string** to cancel and redirect to that path (it wins over the static `guard=` attribute), or an **object** to enter the route and commit the object as the new output-only `<wcs-router>.data` member (`wcs-router:data-changed`, fired first in the commit order, `null` on navigations whose guards return no object; guards on a nested chain are shallow-merged parent → child). This gives routes a loader without a new phase: the guard was already the one asynchronous step before the route content swaps, so a page no longer shows the new route with empty content and a `<wcs-view-transition>` animates real content. Every falsy return still cancels, so existing guards are unaffected.
- `@wcstack/state`: `$errorCallback(error, info)` — an in-page error boundary for bindings. A binding whose application throws (a path getter or filter threw, a structural directive failed) was already isolated from the rest of the batch and reported with `console.error` and to DevTools; declaring this hook on the root state routes the report to the page instead. `info` is `{ path, bindingType, node }`, `this` is the writable state proxy (write the message into state and render it), the hook runs once per failed binding after `$updatedCallback`, is not awaited, and its own exceptions are isolated. DevTools keeps receiving `state:binding-apply-error` either way. Root-only. Exported type `IBindingErrorInfo`.
- Trusted Types: pages that enforce `require-trusted-types-for 'script'` now work with `@wcstack/state` (`innerHTML:` bindings), `@wcstack/router` (layout templates), `@wcstack/fetch` (`target=` HTML responses through an adopter-installed sanitizing policy) and `@wcstack/worker` (`new Worker(src)`). wcstack signs only strings the page author wrote and never signs remote data; see [docs/csp.md](./docs/csp.md) §7 for the policy names to allow. Verified against an enforcing Chromium (`e2e/tests/trusted-types.spec.ts`), which found and fixed two things: a blocked `target=` injection now reports instead of throwing (an automatic fetch had nobody to catch the rejection), and a refused `wcstack` policy with an injected fallback warns once instead of also logging an error.
- `@wcstack/state`: `wcs/default-getter-mismatch` — a two-way binding on a `static wcBindable` property that omits `getter` now warns once per element and property when the event's `detail` cannot be what the property holds: `detail` is `undefined` while the element property has a value (a plain `Event`, or a forgotten `detail`), or `detail` is an object carrying a `<propName>` key while the property is not an object (a `{ value: … }` wrapper). The write is still applied as-is; occurrence properties (`semantics: "event"`) are exempt. Both #234 and #236 were diagnosed by staring at a page that had gone quiet — this makes the second class loud.
- `@wcstack/media-query`: new package — `<wcs-media-query query="(prefers-color-scheme: dark)">` wraps `window.matchMedia` as an I/O node, publishing `matched` / `media` / `supported` through one `wcs-media-query:change` event with `:state(matched)` / `:state(supported)` reflection. Changing `query` while connected re-subscribes (generation-guarded so a stale list can never write), old-Safari `addListener` is handled, and the output is named `matched` because `Element.prototype.matches()` already exists on every element.
- `@wcstack/state`: **a mounted component's getters are exported at its mount point**. A read of a key the tree does not have is answered by the getter of the component mounted there; a key the tree does have wins and warns once (`wcs/mount-export-shadowed`); private keys and methods are never visible. Row mounts export per row, so `$getAll("users.*.display")` and `text: .display` inside the same `for` read each row component's getter, and dependencies flow through — when `user.name` changes, everything that read `user.display` re-renders. Writing to an exported key runs the accessor's setter, or throws when it only has a getter, so the tree never grows a key that would hide the getter. Accessors whose component-local path contains a wildcard (`get "children.*.label"()`) are not exported; mount a component on each row instead. The parent evaluates before the child registers, so the first read may see `undefined` and converges once the component mounts — write derived expressions defensively. This makes **self-recursive components** expressible: the recursion lives in the DOM and the paths are its unrolled form. See [docs/state-overlay-export-design.md](./docs/state-overlay-export-design.md) (#251).

### Changed

- `@wcstack/storage` README: the "persist several inputs as one object" case now has a canonical pattern — an accessor pair (`get formSnapshot()` reading fields by path, `set formSnapshot(v)` restoring them) bound with `value#init=element` — fixed by an integration test against the real `@wcstack/state`. The `$trackDependency` + `trigger` shape is kept as the on-demand variant.
- `@wcstack/state` README: a "Dependency tracking boundaries" table collects the three rules that only show up when crossed (path reads through `this` — `this.form.name` tracks `form` only; reads inside a setter are untracked; the same-value guard is primitive-only), and the binding-authority section opens with the problem `#init=element` solves.
- `@wcstack/router` README: "Where route content lives" — route body by default, `<template data-wcs="if: …">` switching when the DOM must outlive the navigation, with what each costs.
- VS Code extension README: what the analyzer derives from a `$listKeys` entry, spelled out.

- Root `CHANGELOG.md` and `docs/migration-v2.md` added.
- `@wcstack/state` README: documented what a two-way binding writes to state when a `static wcBindable` element fires its change event — `getter(event)`, defaulting to the wc-bindable protocol's `(e) => e.detail` (the whole `detail`, as-is), with the two conforming producer shapes and the `properties[].getter` override. No runtime change: the default is normative for every wc-bindable adapter (#236).
- `@wcstack/signals` README: documented what a property signal receives (`getter(event)`, defaulting to `e.detail`; the initial seed is the one property read) alongside the fix below (#240).
- VS Code extension (ships with the next extension release): the row shape of a list whose initial value is `[]` is now read from row-adding assignments (`concat({ … })`, `toSpliced`, `with`, spread), so `for`-row bindings on those fields no longer report `wcs/binding-path-missing` (#239, #241).

### Fixed

- `@wcstack/state`: assigning to a path that has both a getter and a setter no longer pins the assigned value in the getter cache. Reads after the write re-evaluate the getter, so a normalizing setter is reflected immediately and the getter's dependencies get registered even when the first write is an object (which bypasses the same-value guard). Before, an object assigned through e.g. `<wcs-storage data-wcs="value#init=element: snapshot">` left `snapshot` stale forever (#234).
- `@wcstack/signals`: `bindNode` now applies the wc-bindable default getter (`(e) => e.detail`) to a property that omits `getter`, for both `signals[name]` and `on(name)`. It used to read the element property on each event, diverging from the protocol's MUST, from `@wcstack/state`'s two-way bindings and from `@wc-bindable/core`, so the same element could bind correctly under one adapter and not the other. The initial seed still reads the property. No wcstack I/O node changes behaviour (every getter-less property dispatches its value as `detail`; `<wcs-audio>`'s `noteOn` / `noteOff`, which previously received the same-named command method, are fixed). A third-party element whose getter-less property dispatches a `detail` that is not the property value — or no `detail` at all — now receives that `detail`; declare an explicit `getter` to keep reading the property (#238, #240).

## [2.1.0] — 2026-09-05

### Changed

- `@wcstack/state`: changing `mount=` after the element has initialized now logs a console warning; it was silently ignored. Pre-initialization setup stays silent (#224).
- `@wcstack/state`: `$updatedCallback` no longer receives private mount-marker paths (`#m<id>`). Root and volume-relative delivery both skip them; mount visualization belongs to devtools `overlays()` (#224).
- `@wcstack/router`: the `focus=` and `announce=` getters are normalized to their valid values (`"heading"` / `"title"` or `null`), so `focus=""` or a typo falls back to the browser default reset instead of disabling focus management. When the target route has no visible heading, the router now reproduces the spec-default focus reset itself (`[autofocus]`, else blur to `body`) — focus no longer stays on the previous page's persistent-nav link. Hidden headings are skipped (#227).
- `@wcstack/router`: `<wcs-link>` mirrors `lang` and `dir` onto its inner anchor (#227).
- `@wcstack/devtools`: watch-fired / token-emit measurements are partitioned per state tree, so the coverage tab on a multi-tree page no longer conflates them; the State pane shows per-mount overlays from `overlays(rootNode)` and hides the section on runtimes without it (#225).

### Removed

- `@wcstack/state`: the `name` member of `IStateElement` and the `State.name` getter. It was always `"default"` in v2 and had no consumers. This is a public type-member removal; code that read `stateElement.name` must drop it (#224).

### Protocols

- devtools hook protocol (additive, optional): `state:watch-fired` and `state:token-emit` payloads carry the originating tree's `stateElement`. Old payloads keep working (#225).

### Docs

- i18n design: eight post-landing review findings recorded and resolved; the `router-i18n` example's `mergeAndFreeze` now copies and freezes one-sided subtrees instead of returning them by reference (#226). No package source touched.

## [2.0.0] — 2026-09-04

**State is one tree per root node. It is extended by mounting, not by naming.** The named-state dimension (`<wcs-state name>`, `path@name`) is removed across the runtime, SSR, devtools, manifest, testing, and CLI surfaces. Migration: [docs/migration-v2.md](./docs/migration-v2.md).

### Added

- `@wcstack/state`: `<wcs-state mount="path">` — a *volume*. Its data is grafted onto the root tree at the mount path and read with the `path.` prefix. Getters, `$watch`, `$listKeys`, `$updatedCallback`, and the lifecycle callbacks work relative to the mount. Load order between root and volumes does not matter (#222).
- `@wcstack/state`: `<my-c data-wcs="state: path">` mounts a whole subtree onto a component; its bindings are translated to absolute paths on the host tree at registration (one ledger, no bridging layer). Per-property `state.a: p` keeps working as a partial mount (#222).
- `@wcstack/state`: Light DOM `bind-component` components are written exactly like the Shadow form — no `name`, no `@`, and they can sit on every row of a list (#222).
- `@wcstack/state`: `wcs/mount-own-key-shadow` runtime warning when a mapped component's own data key is shadowed by a mapping (rule R1: own keys are private) (#222).
- `@wcstack/devtools`: hook protocol **v2** with `overlays(rootNode)` (mount records: marker, mount table, delta, private / getter keys) (#222).
- Release tooling: internal `@wcstack/*` dependency ranges are aligned to the released version at bump time, and lockfiles are synced after publish. Before this, `@wcstack/server@2.0.0` would have shipped depending on `@wcstack/state@^1.9.1` (#223).

### Changed (breaking)

| v1 | v2 | How you find out |
|---|---|---|
| `<wcs-state name="x">` | `<wcs-state mount="x">` | runtime fail-fast with guidance; lint error `wcs/named-state-deprecated` |
| `path@x` / `path@default` (in `data-wcs`, `{{ }}`, `<!--@@:-->`, spread, shorthand) | `x.path` / `path` | parse error with guidance; lint error |
| Plain (unwired) Light DOM `bind-component` | add a shadow root, or wire it from the host (`state: path`) | runtime raise with guidance |
| Mapped component's own-key default value | rule R1: own data keys are private and are not overridden by a mapping | `wcs/mount-own-key-shadow` warning |
| Several `<wcs-state bind-component>` wired to one component (different props) | one mount scope per component: merge the wiring or split the component | runtime raise |
| `setInitialState()` re-set on a tree that has grafted volumes or mounts | write the paths you want to change individually | runtime raise (a whole-tree re-set would silently break grafts, accessors, and the ledger) |
| Wildcard-terminal accessor on a mounted component (`get "tags.*"()` translated onto a list of the tree) | a getter on the host tree, or a component-private array | runtime raise |
| `$updatedCallback` receiving other states' paths (`path@name`) | a volume's `$updatedCallback` receives updates under its own prefix as **relative** paths | delivery shape changes |
| SSR `<wcs-ssr name>` / `Ssr.findByName` | name-less `<wcs-ssr>` / `Ssr.find(root)`; old name-carrying snapshots are still readable | — |
| `@wcstack/server` `extractStateData()` (deprecated) | `Ssr.extractStateData()` from `@wcstack/state` | import error |
| devtools hook protocol v1 (`keys` / `read` / `write` with a state name, `stateName` payloads) | protocol v2: `keys(rootNode)` etc., `overlays(rootNode)` | `version: 2` (first-wins) |
| Manifest `states[name].stateSchema` (`schemaVersion` 1) | one `stateSchema` (`schemaVersion` 2); volumes merge as subtrees via `wcs-schema emit --mount=<path>` | readers raise a migration-hint error |
| `@wcstack/testing` `state(name)` | `state()` | an argument throws with a migration hint |
| `wcs-schema --state=<name>` | `--mount=<path>` | usage error with a migration hint |

Declaration surfaces on a volume: `$streams` raises, and `$commandTokens` / `$eventTokens` / `$on` warn — move them to the root state. Everything else a volume declares works mount-relative.

### Performance

Measured on lists whose rows are components: create 1k rows −24%, update −45%, heap −1.5 KB per row. Pages without components or volumes are unchanged (measured gate).

### Fixed

Repairs from the pre-release quality loop, all with tests: `setInitialState` on a grafted tree raised instead of silently wiping; SSR snapshots of volumes were empty; a volume whose `src` failed to load wedged the whole tree and is now isolated; a `Δ=0` delta for `for` indices; own binding text `forPath`; the VS Code extension gained `wcs/mount-path-invalid` (#222).

## [1.32.0] — 2026-08-29

### Added

- **`@wcstack/view-transition`** (new package): `<wcs-view-transition>` arbitrates view transitions for `router` route swaps and `state` list / branch updates through the transition-runner protocol; owns exclusion (`latest` / `queue` / `exhaust`) and the `view-transition-name` policy (#185).
- `@wcstack/state`: `$setAll` — in-place bulk write across a wildcard path with a mapper; arrays broadcast by default (#184).
- binder protocol (`@wcstack/state`, `@wcstack/router`): markup that arrives after startup gets bound (#191).
- `@wcstack/router`: `params` / `typedParams` / `searchParams` / `routeName` as output-only bindable properties on `<wcs-router>`, `replaceUrl`, and a documented firing order (#204).
- Server-side rendering of the initial route: `@wcstack/server` renders it, the client adopts the server DOM, and the new `ssr-snapshot` protocol orchestrates the snapshot pass (#205, #206, #207, #208).
- `@wcstack/router`: warning when stamped markup carries bindings that cannot work (#190); `<wcs-head>` links keyed by `hreflang` (#189).
- Accessibility (phases 0–7): the Navigation API's a11y delegation made explicit (#195); router fallback-mode scroll repair, `aria-current`, attribute forwarding on `<wcs-link>` (#196); `@wcstack/state` keyed reorders use `moveBefore` so focus survives (#197); opt-in `focus=` / `announce=` route policies (#198); `@wcstack/raf` opt-in `prefers-reduced-motion` gate (#199); demo uplift (#200); `wcs/aria-attr-unknown` diagnostic (#201); Accessibility sections in package READMEs and a screen-reader test guide (#194, #202, #203).
- `wcstack` entry package: `wcstack/auto` is now a real SPA-core bundle (state + router + fetch + storage + autoloader) instead of documentation only (#212).
- i18n: design record and reference implementation (`examples/router-i18n`) with the head locale-negotiation snippet; dictionaries are ES modules, no new package (#186, #188, #192).

### Changed

- `@wcstack/state`: `config.locale` defaults to `<html lang>` (previously `'en'`), and the filters' default locale is resolved per application. Pages whose `<html lang>` is not English see `|date` / `|time` / `|datetime` / `|locale` output change (#186, #187).
- `@wcstack/state`: `$getAll(path)` with `indexes` omitted defaults to the enclosing loop context (`[...$n]`); `[]` still means every match. Outside a loop with shared wildcards it throws instead of silently returning everything (#193).
- `@wcstack/router`: a query-only navigation to the same matched route is a *same-match*: guards do not re-run, content is not restamped, no view transition is requested, focus and scroll stay (#204).
- `docs/sri.md`: jsDelivr `/combine/` is forbidden — concatenated minified ESM does not parse and jsDelivr rules out SRI for it (#211).

### Removed

- `@wcstack/router`: `<wcs-route>`'s `static wcBindable` (`params` / `typedParams` / `active`). Binding to a route from `data-wcs` never worked; use the router's outputs. The `wcs-route:*` events are still dispatched (#204).

### Fixed

- `npm-trust-setup --verify` misread every package under npm 11 (#213); completeness guards for the copy-distribution sync scripts (#209); CI builds `@wcstack/state` from source before testing the VS Code extension and lint, so a state change can no longer pass CI while breaking them (#210).
